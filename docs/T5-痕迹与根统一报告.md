## 0. 一句话结论（TL;DR）

1. **模型可见通道再也看不到沙箱**：`ctx.shell` 的 `execute()` 不再往 stderr 注入任何注记（历史形态是
   `[winstage] executed inside the sandbox; real cwd = <暂存树>` + `[winstage] captured N change(s) … frozen candidate …`），
   模型看到的 stdout/stderr **逐字节等于命令自己的输出**；错误文案也全部改成中性措辞（不再有 `winstage-shell:` 前缀）。
2. **同一份诊断仍在**，但只在人工侧三条通道：`handle.winstage.*`（结构化字段）、`ctx.logger`/`logError`（宿主日志）、
   显式诊断文件（`WINSTAGE_DIAG_LOG` / 行 config `diagLog`，**默认零写入**）。
3. **两个根统一**：shell 半边不再回退 `process.cwd()`，改为现读 loader 行表、取 **fs 行的 `cwd`** 作为权威根，
   与 shell 行的 `workspaceRoot` 交叉校验；漂移 ⇒ error 级报警 + 以 fs 根为准；**缺失显式配置 ⇒ 抛错**。
4. **面板能看到命令产出，而且是「立刻」**：两侧解析到**同一个** `getReviewService` 单例，同一个 store 里只有**一份**
   `.dshstage/sessions/<sid>`，`manifest.workspaceRoot` 两侧一致；命令 freeze 之后执行器**有净变化才**补一次
   `service.publish()`（= `/winstage refresh` 同一条调用）⇒ 面板轮询的 `review.json` 当场就有该产出（§4.3、§6.4）。
5. **历史孤儿会话已文档化、未删**：错误根下 7 个会话（1303 条条目、≈133 MB）逐目录列在 §8，
   并附上默认 dry-run 的安全清理脚本 `tools/prune-orphan-sessions.mjs`（自测 11/11；删除须显式 `--apply` 且先导出备份）。

## 1. ★ 验收前置条件（Lead 裁定，必须写进最终验收）

最终"透明沙箱"验收**不是**"随便找个 shell 跑一下验收脚本"，它有三个硬前提（T1 实测结论，Lead 已采纳）：

1. **DSH 侧策略必须是 `danger-full-access`**，让平台层不参与、不混淆 —— 由 winstage 自己提供**唯一一层**强制。
   理由：去令牌化模式要求**启动方自身未受限**；若父进程带着平台的 `WRITE_RESTRICTED` 受限令牌，派生子进程会继承它，
   shim 金丝雀里管道/TLS/系统查询仍然失败 ⇒ 三级探测不通过 ⇒ 自动回退受限令牌模式。
2. **插件必须在未受限的 DSH 宿主进程里调用 executor**，而不是在一个已被平台沙箱包住的 shell 里。
3. `tests/acceptance-transparent.mjs` **必须作为"由 winstage 沙箱托管的命令"运行**才有意义；作为平台受限 shell 命令运行时，
   即使 shim 完美也无法让 T2/T3/T4 变绿（它测的是它自己那个受限上下文）。

另外（T5 发现、Lead 已修的验收台缺陷）：`tests/acceptance-transparent.mjs` 的 **T8** 原先直接读
`<WORKSPACE>/.dshstage/review.json`，而会话隔离后快照落在 `<WORKSPACE>/.dshstage/sessions/<sid>/review.json`
（`review-service.mjs` 的 `sessionStoreDir()`）⇒ 会读到陈旧/空文件。**Lead 已改**为"优先匹配 `DSH_SESSION_ID`，
否则取 `sessions/*/review.json` 里 mtime 最新的一份，并保留旧共享位置兼容"，因此 §1.3 的验收可以直接跑。

## 3. 痕迹清除（task-5 要求 1）

### 3.1 模型可见通道到底有哪几条（读 DSH 源码得到，不是猜）

`dsh-tool-pwsh/lib/index.js` 的 `renderPwshResult()`（:155-176）把 `result.stdout` 与 `result.stderr`

### 3.4 判定力证明（防"假通过"，Lead 强调）

- `shell-selftest` 的 **M5 变异体**：把历史注记按原样加回 stderr（`stderrJoined = stderrOut.text + "\n[winstage] executed inside the sandbox; real cwd = " + stagedDir`
  且 `stderrFinal = boundedOutput(stderrJoined, …)`），断言新契约当场**检出痕迹**（`[winstage]` + 暂存树路径）⇒ 零痕迹断言必然 FAIL。

- ★ 这些断言全部用**替身执行器**走 `execute()` → `settledExecution()` 的**生产渲染路径**，因此**与沙箱开着还是关着无关**：

### 3.5 `run-capture.mjs` / `review-service.mjs` 的复核结论

两者**都没有模型可见通道**（已加注释固化边界）：
- `run-capture.mjs`：`log` 默认 `() => {}`，生产由 host 注入 `ctx.logger`（宿主控制台/日志）；返回值只交给调用方。
  已明确写下"**不要新增 `console.log`/`process.stdout.write`**"，否则"暂存/捕获/候选"字样会回到模型可见面。
- `review-service.mjs`：`logError()` 走 `logger.warn/error` → `console.error`（宿主进程 stderr），**人工侧**；
  它的 `[winstage]` 前缀是给运维/用户看的归因标记，**不得**拼进 `/winstage*` 命令的 `text`（那才会进模型）。

## 4. 工作区根统一（task-5 要求 2）

### 4.1 机制

取值顺序（`shell-executor.mjs:534` `effectiveWorkspaceRoot()` + `shell-entry.mjs:92` `declaredWorkspaceRoot()`）：

1. **loader 行表里 `winstage-fs` 行的 `cwd`** —— fs 半边真正建 Store 用的值（`staging-fs.mjs` 用 `canonical(config.cwd)`），
   因此它是**权威根**；
2. `winstage-shell` 行的 `workspaceRoot`（同一根的另一处声明，bundle 里由 YAML 锚点 `&winstageRoot` 绑死、profile 覆盖层重述）；
3. `configureShellWorkspaceRoot(root)`（行 config 经 `onConfig` 自动调入，落 `this.declaredRoot`）；
4. `WINSTAGE_SHELL_WORKSPACE`（显式诊断逃生口，**不是猜**）。
5. 都没有 ⇒ **抛 `WINSTAGE_SHELL_NO_WORKSPACE_ROOT`**（`declaredWorkspaceRoot()`：`shell-entry.mjs:92-108`）。**绝不再回退 `process.cwd()`**。

**漂移守卫**（`shell-executor.mjs:534-560`）：1 与 2 都存在且不同根 ⇒ **error 级日志**（人工侧，含两个根的原文）
＋ **以 fs 根为准**。宁可响，也绝不让 `getReviewService()` 按两个根分叉出第二个单例。

行表读取 `workspaceRootsOfLoaderRows()`（`shell-executor.mjs:165-191`）**同时兼容**展平行表与 `insert: [...]` 补丁行两种形态
（loader 的 `entry.parent.data` 实测是展平后的条目表；两种都扫，避免形态差异导致守卫静默失效）。

### 4.3 面板仍能看到命令产出（要求 3）

- 根统一后，命令产出与文件工具的改动落在**同一个 store、同一个清单**；面板（`client.js` 的 `readReview()`）读
  `<root>/.dshstage/sessions/<sid>/review.json`。
- 验证台实测：命令（替身执行器）新建 `cmd-output.txt` ⇒ 真捕获链 `captureAfterExecution → ingestCapturedChanges → freezeIfNeeded`
  产出候选（`B11`: `capture.frozen === true`, `captured ≥ 1`）⇒ `service.snapshot()` 的 `files[]` 里有 `cmd-output.txt` 且 `pending === true`
  且有 `+ from-command` 的 diff（`B9/B10`）⇒ 调 `service.publish()`（**与 `/winstage refresh` 按钮同一条调用**，`host-plugin.mjs:240`）
  之后 `review.json` 里同样列出该文件（`B9b`）。
- **命令产出「立刻」可见（task-9 已补上）**：shell 执行完成、候选 freeze 之后，执行器会**有净变化才**补一次
  `service.publish()` —— 与 `/winstage refresh`（`host-plugin.mjs:240`）**完全同一条调用**，因此 `review.json`
  在命令结束的那一刻就列出产出，**不需要**再手动 refresh。无净变化（含只读命令）⇒ **不发布**，不做多余刷盘。
  发布是纯人工侧动作：**不写 stdout/stderr**（零痕迹契约不破），失败只记 error 级日志、**不影响命令退出码与输出**。
  实测：`.t/shell-selftest.mjs` S8.1-S8.10（含"发布失败"与"根守卫"两个反例）＋ M6/M6b 变异体与正对照。
  历史说明（保留留痕）：根统一之前，任何刷新都不可能包含命令产出（它写在另一个根里）；根统一 + 自动发布之后，
  命令产出在**同一个 store** 里生成并**立即**发布到面板轮询的那份 `review.json`。

async function boot(id, rows) {
  const dir = join(base, id)
  mkdirSync(dir, { recursive: true })
  writeFileSync(join(dir, 'entries.json'), JSON.stringify(rows, null, 2), 'utf8')
  const ctx = new Context()
  ctx.baseUrl = `${url(dir)}/`
  await ctx.plugin(Loader)
  await ctx.loader.create({ id: 'include', name: includeModule, config: { path: './entries.json', patches: [] } })
  await ctx.loader.await()
  return ctx
}

    'A5b declaredWorkspaceRoot() body never falls back to cwd',

// ==================== C. static audit of message-string literals ====================
// Every literal that can reach the model (shellFailure() / new Error() messages, stderr notes)
// must be trace-free. This is the code-contract check: it holds whether or not the sandbox
// happens to be enabled (the sandbox state does not change these literals).
{
  const FORBIDDEN = ['[winstage]', '.dshstage', 'staged', 'candidate', 'CAPTURE FAILED', 'executed inside the sandbox']
  /**
   * Collect the full argument text of every `shellFailure(...)` / `new Error(...)` call --
   * those messages are exactly what a thrown execution error puts in front of the model.
   * Balanced-paren scan so multi-line messages are captured whole.
   */
  const callsites = (src, name) => {
    const out = []
    let idx = 0
    for (;;) {
      const at = src.indexOf(name, idx)
      if (at < 0) break
      idx = at + name.length
      const before = src.slice(Math.max(0, at - 1), at)
      if (/[A-Za-z0-9_$.]/.test(before)) continue // skip qualified/member occurrences
      let depth = 0
      let i = at + name.length
      for (; i < src.length; i += 1) {
        if (src[i] === '(') depth += 1
        else if (src[i] === ')') {
          depth -= 1
          if (depth === 0) break
        }
      }
      out.push(src.slice(at, i + 1))
    }
    return out
  }
  const offenders = []
  for (const file of ['dsh-plugin/shell-entry.mjs', 'dsh-plugin/shell-executor.mjs']) {
    const src = readFileSync(join(REPO, file), 'utf8')
    for (const call of [...callsites(src, 'shellFailure'), ...callsites(src, 'new Error')]) {
      for (const token of FORBIDDEN) {
        if (call.includes(token)) offenders.push({ file, token, call: call.slice(0, 200) })
      }
    }
  }
  check(
    'C1 no thrown-error message (shellFailure / new Error) in the shell half carries a sandbox trace',
    offenders.length === 0,
    { offenders },
  )
  const shellSrc = readFileSync(join(REPO, 'dsh-plugin/shell-executor.mjs'), 'utf8')
  check(
    'C2 the old stderr-note builder is gone from settledExecution (no stderrNotes)',
    !shellSrc.includes('stderrNotes'),
  )
  check(
    'C3 shellFailure() no longer prefixes the model-visible message',
    !/new Error\(`winstage-shell:/.test(shellSrc),
  )
  check(
    'C4 model-visible stderr is assembled from the command stderr ONLY (two exact assignments, no concat)',
    shellSrc.includes('      const stderrJoined = stderrOut.text\n') &&
      shellSrc.includes('      const stderrFinal = stderrOut\n') &&
      !/stderrJoined\s*=\s*stderrOut\.text\s*\+/.test(shellSrc) &&
      !/stderrFinal\s*=\s*boundedOutput\(stderrJoined/.test(shellSrc),
  )
  check(
    'C5 positive control: the callsite scanner really extracts messages (>=15 callsites found)',
    callsites(shellSrc, 'shellFailure').length >= 10,
    { found: callsites(shellSrc, 'shellFailure').length },
  )
}
