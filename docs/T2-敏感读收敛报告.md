## 3. task-7：`isReparsePoint()` 恒 false —— 一条**从未生效**的逃逸判据

### 3.1 缺陷与"为什么长期假绿"

`src\workspace.mjs` 旧判据：

```js
function isReparsePoint(info) {
  if (info.isSymbolicLink()) return true
  return (Number(info.mode ?? 0) & 0x400) !== 0   // ← 作者以为是 Win32 FILE_ATTRIBUTE_REPARSE_POINT
}
```

`[实测]` Node 的 `fs.Stats` **没有 `attributes` 字段**，`mode` 是 POSIX 位：
普通目录 `0o40666`、junction 同样 `0o40666` ⇒ `& 0x400` **恒为 false**，
而 `lstatSync(junction).isSymbolicLink()` 在本机也是 **false**（见 §3.2 表）
⇒ **junction 守卫从未生效**（README §16.6 / §16.7 的"符号链接不能绕过"链路）。

**长期假绿的原因**：`tests\workspace-regressions.mjs` 的 D8 用 `cmd /c mklink /J` 建 junction，
受限会话里起不了 `cmd.exe` ⇒ 走 `--SKIP--` 分支 ⇒ **D8 在最需要它的场景里一次都没真跑过**。
本会话沙箱关闭后 `mklink` 成功，D8 立刻以
`ELOOP: too many symbolic links encountered`（自指 junction）露出真相。
性质与 README 缺陷 11（"空结果被当成拒绝"）同级：**假通过**。

### 3.2 判据选型：五个候选逐个实测（`--probe-reparse` 原始输出）

```
node tests\workspace-regressions.mjs --probe-reparse
```

| 对象 | `lstat.isSymbolicLink()` | `mode & 0x400` | `readlinkSync()` | `realpath.native()` | `dirent.isSymbolicLink()` |
|---|---|---|---|---|---|
| 普通目录 | false | false | `EINVAL` | 等于自身 | **false** |
| 普通文件 | false | false | `EINVAL` | 等于自身 | **false** |
| junction（`fs.symlinkSync(…,'junction')`） | **false** | false | `EINVAL` | **解析到目标** | **true** |
| junction（`cmd mklink /J`） | **false** | false | `EINVAL` | **解析到目标** | **true** |
| `C:\Users\ADMINI~1`（8.3 短名，**非**重解析点） | false | false | `EINVAL` | **解析到长名** | false |

原始片段（本会话实跑）：

```

  cmd mklink /J 结果：status=0 error=- exists=true
  ── plain-dir（普通目录）

                            {"name":"junction-mklink","isSymbolicLink":true,"isDirectory":false},

```

**被实测否定的三个候选**：① 只靠 `lstat.isSymbolicLink()`（对 junction 为 false）；
② `readlinkSync()`（对 junction 抛 `EINVAL`，Node 的 readlink 不覆盖 junction）；
③ 只靠 `realpath.native` 前缀比较（会把 **8.3 短名目录**误判成重解析点 ⇒ 静默漏采真实内容，比原缺陷更糟）。

**采纳的判据（三层，逐层可独立证伪）**：

```js
function classifyEntry(item, dirent) {           // src/workspace.mjs
  if (dirent?.isSymbolicLink?.()) return 'reparse-point'          // ① 实测唯一可靠信号
  const info = lstatSync(item)
  if (info.isSymbolicLink()) return 'reparse-point'               // ② 跨平台第二防线
  if (info.isDirectory() && dirent?.isDirectory?.() === false) return 'reparse-point' // ③ 交叉校验
  return undefined
}
```

### 3.3 walker 环路防护（独立于判据）与结构化跳过

`walkStagedForHashes()` 现用 `readdirSync(dir,{withFileTypes:true})`，并有四层纵深防御：

| 层 | 机制 | 生效证据（`--plant` 实测） |
|---|---|---|
| 1 | `classifyEntry()` 判据 | 正常模式：junction 记为 `reparse-point` |
| 2 | **祖先链**环路检测（解析后身份，大小写不敏感）`ancestors` | 变异体 P2：记为 `cycle-detected`，不崩 |
| 3 | 硬深度上限 `WALK_MAX_DEPTH=64` | 变异体 P3：记为 `unreadable:ELOOP` / `depth-limit`，不崩 |
| 4 | `lstat` 失败的**保守 catch**（跳过并记录原因） | 变异体 P4：三层显式防护全拆仍不崩，记为 `unreadable:ELOOP` |

跳过项**结构化上报**（不再是一句"跳过了"）：
`snapshotStagedTree()` 返回值上挂 `skippedReparsePoints: string[]`（兼容）
与 `skipped: Array<{path, reason}>`，`reason ∈ reparse-point | cycle-detected | depth-limit | unreadable:<CODE>`。
`captureAfterExecution()` 共用同一 walker ⇒ junction 也**不会**被误判成"被命令删除的文件"。

`--plant` 用**文本改写 `src\workspace.mjs` 的副本**（锚点必须全部命中，否则断言先红），

## 4. 诚实声明（必须与"通过"一起读）

1. **遮蔽表仍然是黑名单，不是硬边界**（README §8.3 已承认，本轮不改变这一事实）：
   把 `Login Data` 复制成 `login.db`、把 `History` 改名 `h.db`、换一个不含 profile 字样的目录形状，
   都能绕过本表。本表的定位是**工具层检测/兜底**；真正的读面硬边界是 T0（AppContainer）。
2. **不新开 id 是刻意的**：`src\audit.mjs::READ_PROBES` 与 `MASK_CLASSES` 之间有**双向覆盖契约**
   （`tests\audit-parse.mjs` 用 `READ_PROBE_MISSING_MASK_CLASSES` 强制"每个遮蔽类都要有读取探针"），
   而 `audit.mjs` 不在 T2 写入范围。为不把 `verify.cmd` 弄红又不越界，新形状**并入既有类**
   并同步改 `category`/`reason` 文字。若要把 `History` / `NTUSER.DAT` / PSReadLine 单独立类，
   需**同时**在 `audit.mjs` 的 `READ_PROBES` 补探针（补丁见下），否则 `audit-parse` 会红。
3. **"不存在"不等于"被挡住"**：`%APPDATA%\acme.credentials`、非 AppData `Network\Cookies`/`History`
   在本机**不存在**（`not-present`），它们是**形状探针**（命名约定类），不构成"我们挡住了"的证据。
4. **`denied` 也不能归因于我们**：`System32\config\{SAM,SECURITY,SYSTEM}` 的 `EPERM` 来自系统 ACL，
   与遮蔽表无关（README §8.3 同口径）。`NTUSER.DAT` / Edge `Network\Cookies` 是 `EBUSY`（被占用），
   属"能列出、读不出"，**不记"被拒绝"**。
5. **`proven=true` 的隔离证据不是本轮产生的**：来自 `.t/sbx3/dev/raw-t0-isolation-proof.txt` 等
   上一轮真机证据；本轮只**接线与判定**，没有重跑真实隔离探针（需未受限会话）。

**若要单独立类**，`src\audit.mjs` 需追加（示意）：

## 7. task-10：给 shim 的机器可读遮蔽清单（T2 半边）

### 7.1 产出与用法

```powershell
node src\paths.mjs --export-mask mask.json     # 写文件（stderr 打印条数）
node src\paths.mjs --export-mask -             # 写 stdout
```

`schema: winstage.mask.v1`，字段：

| 字段 | 含义 |
|---|---|
| `entries[]` | `{ id, kind: 'file'\|'dir'\|'glob', pattern, flags, matchMode:'casefold', category, reason }` |
| `probes[]` | `{ id, path, maskClass }` —— **自检样本**：shim 实现完匹配后必须对每条探针复现出 `maskClass` |
| `normalizer` | `{ name:'maskKey', steps[], invariant }` —— 归一化语义的**唯一来源**声明 |
| `counts` | `{ rules, probes, selfMaskId }` |

**消费方必须遵守的三条**（写进导出契约，T4 实现读它）：
1. **先归一化再匹配**：`maskKey()` 语义 = `realpathSync.native`（解析 symlink/junction、8.3 短名、
   `\\?\` 长路径前缀、`.`/`..` 折叠）+ 去结尾分隔符 + 统一 `\`；匹配按 `flags` 的 `i` 大小写不敏感。
   ⇒ `mklink /J` 一个指向敏感目录的 junction **不能**绕过。
2. **顺序即优先级**：命中取**第一条**匹配的条目（与 `maskReason()` 逐字一致）；
   因此导出**保持 `MASK_CLASSES` 的原序**，`browser` 之类宽规则仍在其窄规则之前。
3. **黑名单 + 只覆盖被 hook 的路径**：未列出的敏感对象仍可读；未注入的进程不受管。

### 7.2 为什么它不会变成"第二套实现"（防漂移断言，`tests\paths-masks.mjs` §8）

| 断言 | 判据 |
|---|---|
| 条目数 == 内部表条目数 | `entries.length === MASK_CLASSES.length`，`counts.rules` 同值 |
| **逐条同源** | id / 顺序 / `pattern` 源串 / `flags` / `reason` / `category` 与 `MASK_CLASSES[i]` 全等 |
| **独立复算** | 用导出的 `(pattern, flags)` 重新编译并复算 **68 条探针**，每条的 id 必须与 `maskReason()` 逐字一致（含"顺序即优先级"） |
| 探针随行 | `probes.length === MASK_PROBES.length` 且 id / `maskClass` 逐个一致 |
| 归一化唯一来源 | `normalizer.name === 'maskKey'`，且不变式 `maskKey(dir) === maskKey(dir + '\\')` 当场成立 |
| CLI 往返 | `node src\paths.mjs --export-mask <file>`（fd 重定向捕获，不用命名管道）exit 0，写出的 JSON 与 `exportMaskList()` **逐字段一致**（仅 `generatedAt` 不同） |

`[实测]` `tests\paths-masks.mjs`：**58 断言 / 0 失败**，其中 §8 的 11 条即上表；
`--plant` 仍见红（exit 1）。
