## 1. 不就地改写调用方结构 —— PASS

- `ws_file.c:1483` `OBJECT_ATTRIBUTES ws_oa = *ObjectAttributes;`（**值拷贝**）；
- `:1484-1488` `UNICODE_STRING ws_un; ws_un.Buffer = ws_map; …; ws_oa.ObjectName = &ws_un; ws_oa.RootDirectory = NULL;`
  ⇒ 只有**本地副本**被改；`ws_map` 是栈上缓冲。
- 调用方结构全程只读：`:1470`（`ObjectAttributes ? ObjectAttributes->ObjectName : 0`）、`:1473`（`ObjectAttributes->RootDirectory == NULL`）、`:1483`（`*ObjectAttributes`）。

## 2. 不可能 fail-closed —— PASS（出口穷举）

`ws_NtQueryInformationByName` 的**所有**出口（apply 后）：

| 出口条件 | 行为 |
|---|---|
| `t_wsFileBusy>0` / `ws_nqifbn_orig==0` / `IoStatusBlock==0` / `ObjectAttributes==0` / `ObjectName==0` / `Length==0` / `Length` 超长 / `RootDirectory!=NULL` | 门条件不成立 ⇒ **跳过整块**，落到 `:1523` 起原有代码（`ws_nqifbn_orig` 或裸 `NtQueryInformationByName`） |

| `GetFullPathNameW` 返回 0 | `ws_strlcpy_w(ws_abs, ws_nz, WS_PATH_MAX)` 后**仍继续解析**（不是失败返回） |

| **`ws_stat_resolve` 返回 1（whiteout）** | 唯一不回落的出口 —— **规格 §3②(白色)明令**：填 `0xC0000034` 并直接返回 |

⇒ 没有任何一条"异常 ⇒ 返回失败/伪造成功"的路径；与交接件 §3「未命中 / 路径未变 ⇒ 原样透传」「任何异常 ⇒ 一律回落真实 API、绝不 fail-closed」一致。

## 3. whiteout 分支不伪造成功 —— PASS（但**须由 ③ 的负对照封口**）

`:1495-1502`：`IoStatusBlock->Status = (NTSTATUS)0xC0000034; IoStatusBlock->Information = 0;` 打日志后 `return ws_gone;`
⇒ **函数返回值与 IOSB 一致**，且**不调真实 API**。这是"按契约伪造不存在"，不是伪造成功。

**残留风险（我要求 ③ 补负对照，否则本条无法证伪）**：`ws_stat_resolve` 的 `return 1` 只由 provider 的 `WINSTAGE_RES_WHITEOUT` 决定（`ws_file.c:860-861`），**它不检查真实盘上是否其实存在该文件**。若 provider 把"真实存在的文件"误判为 whiteout，则**真实盘文件的 `statSync` 会变成 ENOENT**（对真实文件过度回答）。
⇒ ③ 必须包含：**对真实盘（非暂存）文件做 `statSync`，必须仍成功**。缺这一条，"未改坏真实盘语义"未被检验。

## 5. 缓冲与长度安全 —— PASS

- `WS_PATH_MAX = 4096`（`shim\src\winstage_internal.h:24`）。
- `ws_nz[WS_PATH_MAX]` 写入前有门：`ws_us->Length <= (ULONG)((WS_PATH_MAX-1)*sizeof(wchar_t))`（`:1474`）⇒ `ws_n ≤ 4095`，`ws_nz[ws_n]` 合法。
- `ws_un.Length = (USHORT)(wcslen(ws_map)*2)`，`ws_map` 最坏 4095 字符 ⇒ 8190；`MaximumLength = Length+2 = 8192` ⇒ **USHORT 不回绕**（骨架版本在 `WS_PATH_MAX` 更大时会回绕，此处因 4096 无风险）。
- 代价：单次调用栈上 3 × 8,192 B = **24 KB**（`ws_nz`/`ws_abs`/`ws_map`）。观察项，非缺陷。

## 6. 命名空间处理 —— PASS，附低风险残留

- `\??\UNC\…` → 还原成 `\\server\share\…`（`:1505-1509`）；`\??\C:\…`（盘符绝对）→ 剥成 `C:\…`（`:1510-1516`）。
- 明确**不剥**：`\??\C:x.txt`（驱动器相对）、`\??\Volume{…}`（卷 GUID）⇒ 落进黑名单透传（`:1518-1519`）。
- 残留：`\SystemRoot\…`、`\Registry\…` 等**其它 NT 根不在黑名单**，会被 `GetFullPathNameW` 编成假盘符路径（如 `C:\Registry\…`）；随后解析链几乎必然 `isStaged=0` ⇒ **透传**。⇒ 低风险（只有在覆盖层恰有此假路径时才可能错答），记录为观察项。

## 7. 日志字段 —— PASS

## 9. 与权威规格/交接件骨架的差异（须上报 Lead）

1. **绝对化顺序**：交接件 §3 骨架写 `GetFullPathNameW(namez, …)`（直接对 NT 名调用）；本实现**先剥 `\??\` 前缀再绝对化**（`:1503-1517`），并在补丁注释里给出 D96 实测依据（`GetFullPathNameW` 会把 `\??\C:\x` 编成 `C:\??\C:\x`）。
   ⇒ 这是**对规格意图的正确实现**（规格 §6 只要求"拼成绝对路径"，未规定对 NT 前缀的处置），但**与骨架代码不同**，按交接件 §1「与实现冲突时以规格为准，并向 Lead 回报差异」的口径上报。**我不判定为偏离**：规格未禁止，且不加这一步解析链必然 no-op（D95 第 0 步已实测）。
2. `_wcsicmp`（骨架）→ `ws_wcscmp_ci`（实现）：等价，且实现用了本仓既有工具函数（符合"复用不要自创"）。
3. 骨架 whiteout 分支只填 IOSB；实现额外 `Information=0`（与规格 §3② 逐字一致）。
