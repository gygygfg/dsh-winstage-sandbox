## 3. 便携 exe 运行完整性（任务项 2）：**字节完整性成立 / 运行完整性不成立**

### 3.1 运行前后哈希（run-3，TS 档）

| 产物 | before | after | 一致 |
|---|---|---|---|
| `7zr.exe` | `256feca8…d282` (602624) | 同 | ✅ |
| `7z2604-x64.exe` | `d54bf805…a665d` (1664082) | 同 | ✅ |

⇒ **沙箱没有改写被执行/被依赖的 PE 字节**（这条是"字节完整性成立"）。

### 3.2 但第三方便携 exe **跑不起来**（0xC0000005）

| 读者 | 档位 | `7zr.exe` 结果 |
|---|---|---|
| run-3（主证据） | TS（shim） | `7zr i` → **`3221225477` = `0xC0000005`（STATUS_ACCESS_VIOLATION）**；`7zr a`/`7zr t` 同样崩溃；归档未生成 |
| run-4（第二次独立会话） | TS（shim） | `7zr i` ×2 → **两次都是 `0xC0000005`**（5/5 累计） |
| run-1（作废） | T1（受限令牌） | `7zr i` / `a` / `t` → **exit 0**（3/3 成功） |
| run-2（平台对照） | 无沙箱 | `7zr i` / `a` / `t` → **exit 0**（3/3 成功），归档 159 B 生成 |

**判别性**：同一个二进制、同一组参数、同一种"原生 stdout 走真实 fd 重定向"的写法 —— **垫片开 ⇒ 崩；垫片关（T1 或平台）⇒ 正常**。
同一次 run-3 中 `node --version` exit 0、文本写正常、`7z2604-x64.exe /S` exit 0 ⇒ 不是"沙箱一律起不了进程"，而是**垫片的子进程注入在 7zr.exe 上出事**。
`shim.log` 侧证：每个 7zr PID 都留下 `child injection armed ok=1` / `hooks installed: 319 IAT sites across 28 modules`，随后**无 shutdown 记录即截断**（`evidence/07` §A）。

⇒ **判定：便携 exe 运行完整性不成立**（第三方 exe 在默认 TS 档不可用）。这是本域最严重的产品缺陷（见 `defects.md` D-EXE-4）。

### 3.3 写入行为（run-3，TS 档）：**全部重定向进暂存**

| 目标 | 结果 | 暂存镜像 |
|---|---|---|
| 沙箱 cwd（`<stage>\staged`） | `ok` | —（本身即暂存根） |
| **真实工作区路径** | `ok` | `staged\fs\C\…\.t\round10\exe\ws\run3\…` ✅ 镜像出现 |
| `%LOCALAPPDATA%` / `%APPDATA%` | `ok` | ✅ 镜像出现 |
| `C:\Program Files` | `ok` | ✅ 镜像出现 |
| `C:\ProgramData` | `ok` | ✅ 镜像出现 |
| `C:\Windows\Temp` | `ok` | ✅ 镜像出现 |
| `Desktop` | `ok` | ✅ 镜像出现 |
| 会话 TEMP（被改写为 `…\dsh-stage-temp\<uuid>`） | `ENOENT`（父目录不存在） | — |

**关键**：这里"`ok`"**不代表写进了真实盘**——每个 `ok` 都伴随一个 `staged\fs\C\…` 镜像文件；宿主侧复核这些真实路径**全为 `False`**（§5）。`sandbox-audit.json` 把这些记为 `filesWrittenOutside=295`（"工作区外"），**其语义是"工作区外、已进暂存"，不是"写到宿主"**（见 D-EXE-10）。

T1 档（run-1，作废但仍有效说明机制）：同样的矩阵**全部 `EPERM`**，且**没有**暂存镜像 ⇒ T1 是"硬拒"，TS 是"重定向"。两种都是隔离，但**机制与可观测行为完全不同**。

### 3.4 反例（作废 run 里的机制说明）：`requireAdministrator` 安装器在创建阶段被拒

- 静态证据：`7z2604-x64.exe` 的 PE manifest 含 **`requireAdministrator`**；`7zr.exe` 是 **`asInvoker`**（`evidence/06` §C）。
- 动态证据（run-1，T1）：`spawnSync(7z2604-x64.exe /S /D=…)` → `error=EACCES`（`CreateProcess` 层失败），零落盘；同 run 的 `7zr.exe` exit 0。
- 结论：**要求提权的安装器在受限/非提权令牌下连"启动"都做不到**。含义是"需要管理员权限的安装器无法在沙箱内安装（也无法在沙箱内被评估完整性）"——这是设计边界，必须显式写给使用者（D-EXE-5）。

## 8. 诚实边界（not-run / 未定论）

1. **`winstage-probe.exe selftest`（仓库自身的 shim 完整性门）未在沙箱内运行**：`not-run`。原因是它需要显式加载 shim，而本轮已发现 shim 会让 7zr 崩溃，做这个检查的收益与风险都不明；仓库自身产物完整性仍只有 §2 的静态结论。
2. **`0xC0000005` 的根因未定位到代码级**：只证到"垫片开启 ⇒ 崩、关闭 ⇒ 不崩；node/安装器不崩"。**未做**最小化复现（例如换一个纯控制台 exe）与 dump 分析。
3. **安装器 `exit 0` 后是否有子进程继续运行**：`tasklist` 在 TS 下可用（exit 0）但本域未对安装器进程树做逐 PID 追踪；宿主侧只按名称抓了 `7z/winstage/msiexec`。
