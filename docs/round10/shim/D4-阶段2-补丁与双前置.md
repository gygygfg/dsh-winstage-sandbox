## 1. 授权、执行说明与一处事实澄清

Lead 指示的三条硬性约束：① 用**本地表 + 真实解析器指针同一性**实现序数路由；② **不改** `g_orig` / `winstage_internal.h`；③ **不动** `ws_file.c`。本补丁全部遵守。

**一处事实澄清（不改变执行，仅纠前提）**：`shim/src/winstage_internal.h` 的 `WsOriginals` **本来就已有**这 6 个字段（`:137-142`：`GetFileInformationByHandle` / `NtQueryInformationFile` / `GetFileInformationByHandleEx` / `NtQueryAttributesFile` / `NtQueryFullAttributesFile` / `NtQueryInformationByName`），且 6 个包装函数也已在 `:153-158` **声明**（`ws_hook.c` 包含该头文件 ⇒ **不需要**再写 `extern`）。因此"往 `map[]` 加条目就必须改头文件"这一步并不成立。

尽管如此，我**仍然按指示没有用 `g_orig`**，理由有两条（也说明这个选择更优）：
1. `ws_file.c` 里这 6 个包装读的是**各自的 file-static**（`grep 'g_orig\.(那 6 个名字)' shim/src/ws_file.c` 只命中 `:1285 g_orig.GetFileInformationByHandle` 与 `:1336 g_orig.GetFileInformationByHandleEx`）⇒ 往 `map[]` 填 `g_orig` 对其中 4 个是**惰性**的；
2. 但填 `g_orig` 会改变两处**可见行为**：`ws_hook_original_by_name()`（导出面 `WinstageShimOriginal`）与 verbose 安装日志的 `original=NULL/yes`。本地表 `g_d4OrdMap[]` 完全内聚在 `ws_hook.c`，**这两处保持逐位不变**。

**一处超授权的补充（请 Lead 追认或否决）**：把同一指针同一性规则**也**接到 `ws_LdrGetProcedureAddress` 的**序数分支**（`ProcedureNumber != 0`）。理由：它是同一解析原语的另一入口；只修 `GetProcAddress` 的序数会留下**同形缺口**（阶段 1 的 `rawldr` 路由证明该入口确实存在）。无新挂钩目标、无新文件、复用同一 helper，回滚只需删 8 行（§7）。

## 2. 改动内容（`ws_hook.c`，两个 hunk）

### 2.1 (i) `ws_GetProcAddress`：**先问真实解析器，再决定是否换**

```c
FARPROC WINAPI ws_GetProcAddress(HMODULE hModule, LPCSTR lpProcName)
{
    if (!g_orig.GetProcAddress) {
        return NULL;                    /* orig 未解析 ⇒ 只能 fail-safe，绝不伪造 */
    }
    FARPROC real = g_orig.GetProcAddress(hModule, lpProcName);   /* ★ 先问真身 */
    if (!real || !lpProcName) {
        return real;                    /* 真实结果 NULL ⇒ 原样 NULL（不再"发明"） */
    }
    if ((ULONG_PTR)lpProcName > 0xFFFF) {
        void *rep = ws_hook_resolve(lpProcName);
        return rep ? (FARPROC)rep : real;   /* 非 NULL 且名字命中 ⇒ 换包装 */
    }
    void *wrap = ws_wrapper_for_real((const void *)real);       /* (ii) 序数 */
    return wrap ? (FARPROC)wrap : real;
}
```

| 情形 | 旧行为 | 新行为 | 判据 |
|---|---|---|---|
| 名字命中，且 `hModule` **确实导出**它 | 包装 | 包装（先 real 非 NULL） | A/B 实测：`ntdll!NQIFBN`、`kernel32!CreateFileW` 均为包装 |
| 名字命中，但 `hModule` **不导出**它 | **包装（发明）** | **`NULL`**（= 真实 loader） | A/B：`kernel32!NQIFBN`、`kernel32!NtOpenFile` 均由包装→`NULL` |
| `hModule == NULL` | **包装（发明）** | **`NULL`** | A/B：同 |
| 名字不在目标表 | 真实结果 | 真实结果（同一次真实解析） | A/B：`NtClose`、`GetModuleHandleW` 不变 |
| `g_orig` 未解析 | `NULL` | `NULL` | 静态审查（D-FILE-2 精神：fail-safe，不伪造、不 fail-closed 出错码） |

- **重入/自调用**：`real` 来自 `g_orig.GetProcAddress`（初始化期从 kernelbase/kernel32 **直接**取得的真身指针，且 shim 自身模块从不被补丁）⇒ **不经我们自己的钩子**，无自陷；`ws_hook_resolve` 只查静态名表（无 I/O、无 API 调用）。
- **成本有界**：非覆盖名本来就是"调一次真实解析"（与旧代码相同）；只有 ~60 个覆盖名比以前多一次真实解析（旧代码对它们短路返回）。

### 2.2 (ii) 序数路由：**真实指针同一性**

```c
/* 本地表：这 6 个目标的 orig 由 ws_file.c 各自持有，ws_hook.c 不能填 g_orig */
typedef struct WsOrdEntry { const char *name; void *wrapper; void *real; } WsOrdEntry;
static WsOrdEntry g_d4OrdMap[] = {
    { "GetFileInformationByHandle",  (void *)ws_GetFileInformationByHandle,  0 },
    { "NtQueryInformationFile",      (void *)ws_NtQueryInformationFile,      0 },
    { "GetFileInformationByHandleEx",(void *)ws_GetFileInformationByHandleEx,0 },
    { "NtQueryAttributesFile",       (void *)ws_NtQueryAttributesFile,       0 },
    { "NtQueryFullAttributesFile",   (void *)ws_NtQueryFullAttributesFile,   0 },
    { "NtQueryInformationByName",    (void *)ws_NtQueryInformationByName,    0 },
};

static void *ws_d4_ord_real(WsOrdEntry *e)
{
    void *p = (void *)InterlockedCompareExchangePointer((void *volatile *)&e->real, NULL, NULL);
    if (p) return p;                                  /* 已解析（CAS 读） */
    if (!e->name || !g_orig.GetProcAddress) return NULL;   /* 无真身解析器 ⇒ 不换 */
    const HMODULE order[] = { g_orig.hKernelBase, g_orig.hKernel32, g_orig.hAdvapi32, g_orig.hNtdll };
    for (size_t k = 0; k < 4 && !p; k++)              /* 与 ws_hook_init 同序（只多一次 ntdll） */
        if (order[k]) p = (void *)g_orig.GetProcAddress(order[k], e->name);
    if (p) { void *prev = InterlockedCompareExchangePointer((void *volatile *)&e->real, p, NULL);
             if (prev) p = prev; }                    /* 并发只影响首解析，后者用先到值 */
    return p;
}

static void *ws_wrapper_for_real(const void *addr)
{
    if (!addr) return NULL;
    for (size_t i = 0; i < WS_TARGET_COUNT; i++) {            /* ① 已捕获的 orig */
        if (!g_targets[i].originalSlot || !*(g_targets[i].originalSlot)) continue;
        if (*(g_targets[i].originalSlot) == addr && ws_family_enabled(g_targets[i].name))
            return g_targets[i].replacement;
    }
    for (size_t i = 0; i < sizeof(g_d4OrdMap)/sizeof(g_d4OrdMap[0]); i++) {  /* ② 本地表 6 项 */
        if (!ws_family_enabled(g_d4OrdMap[i].name)) continue;
        if (ws_d4_ord_real(&g_d4OrdMap[i]) == addr) return g_d4OrdMap[i].wrapper;
    }
    return NULL;                                              /* 不匹配 ⇒ 不换 */
}
```

`ws_LdrGetProcedureAddress` 追加（同规则、无新目标）：

```c
    } else if (st >= 0 && ProcedureNumber != 0 && ProcedureAddress && *ProcedureAddress) {
        void *wrap = ws_wrapper_for_real(*ProcedureAddress);
        if (wrap) *ProcedureAddress = wrap;      /* 不匹配/未解析 ⇒ 保持真实地址 */
    }
```

**规则与安全性质（四条"不换"全为安全侧）**：`addr==NULL` 不匹配；orig 未捕获的 g_targets 项**跳过、绝不猜**；被 `WINSTAGE_SHIM_SKIP` / family 开关关掉的目标跳过；本地表解析失败 ⇒ 保持透传。**不需要遍历导出表/名字表**，也不需要知道序数→名字关系（loader 已把结果算给我们）。

**已知边界（保守、明写）**：① `kernel32` 的**转发序数 stub** 与其 `kernelbase` 实现**不同址** ⇒ 这类序数**不会**被替换（保持透传，绝不误换）；② 别名导出共享同一地址 ⇒ 替换成语义等价的那一个包装（两者都转发到同一真实实现）。
