### 1.1 两个入口的"同名不同址"（逐字指针行）
| 入口 | 修前 `count18`（arm2） | 修后 `count19`（arm3） |
|---|---|---|
| `GetProcAddress` | `SAMENAME_GPA ptr=0x6fbf3890 class=S real_test=0x6fbc1000 verdict=FAIL(hijacked)` | `SAMENAME_GPA ptr=0x6fbc1000 class=R real_test=0x6fbc1000 verdict=PASS` |

**机制注记（防误读）**：带 shim 时本 exe 的**静态导入 IAT 槽** `LdrGetProcedureAddress` 仍是 `class=R`（`IATSLOT LdrGetProcedureAddress slot=0x7ffb636760f0 real=0x7ffb636760f0 class=R`，该槽未被改写），而**调用方真正拿到的入口**是 `LDR_VIA_GPA ptr=0x6fbf6460 class=S`。⇒ Ldr 判定必须走**调用方可见的入口指针**；走未改写的静态槽会得到假阴性（本探针首版即如此，已修正，并把两条路径同时打印）。

### 1.2 覆盖零丢失（独立复算 19 名 × 4 模块，class 级 diff）
```
<= LDRCOV LdrGetProcedureAddress  … cov=kb:N k32:N adv:N nt:R      (count18 PRE)
=> LDRCOV LdrGetProcedureAddress  … cov=kb:N k32:N adv:N nt:S      (count19 POST)
```
⇒ **修前→修后 class 级矩阵唯一差异就是 `LdrGetProcedureAddress` 自身 `nt:R→nt:S`（预期的覆盖增益）**；`MODMAP`/`LDRCOV` 其余全部逐项相同：`GetFileAttributesW/CreateFileW/GetFileInformationByHandle(Ex)/MoveFileWithProgressW` → `kb:S k32:S`；`Reg*` 族 → `kb:S k32:S adv:S`；`LdrLoadDll/NtQueryInformationByName/NtQueryInformationFile/NtQueryAttributesFile/NtQueryFullAttributesFile/NtOpenFile/NtSetInformationFile` → `nt:S`；`NtClose` → `nt:R`。
`K32_VS_KB`：修前修后均 `samePtr=1` 且**两模块都=包装** ⇒ `PASS(coverage-retained)`（该名两模块都拥有，必须继续给包装，不是缺陷）；无 shim 臂为 `samePtr=0` 且各自真身 ⇒ 语义自洽。

### 1.3 两条窄边界（显式读数）
- **(a) `len ≥ 128` ⇒ 不替换**：`LONGNAME len=219 st=0xC0000139 ptr=0x0 class=N verdict=PASS(not-replaced)`（**修前/修后同**）。名字 = 覆盖名 + 200×`A`（总 219 字节）经 Ldr 入口 ⇒ **从不返回我们的包装**（该名不存在，加载器返回 `STATUS_ENTRYPOINT_NOT_FOUND`）⇒ 属**保守不替换**，不是覆盖丢失。
- **(b) 每个覆盖名至少能在四模块之一解析到**（我方 PE 独立复算，19/19）：`kernelbase,kernel32`＝`GetFileAttributesW/CreateFileW/GetProcAddress/LoadLibraryW/GetFileInformationByHandle(Ex)/MoveFileWithProgressW`（count=2）；`+advapi32`＝`RegCreateKeyExW/RegQueryValueExW/RegDeleteValueW`（3）；`ntdll`＝`LdrLoadDll/LdrGetProcedureAddress/NtQueryInformationByName/NtQueryInformationFile/NtQueryAttributesFile/NtQueryFullAttributesFile/NtOpenFile/NtSetInformationFile/NtClose`（1）。**最小 count=1，无 0** ⇒ 名字路径对这 19 名均可命中。
