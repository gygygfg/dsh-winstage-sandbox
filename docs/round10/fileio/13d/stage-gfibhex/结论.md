## 2. 结论：**不可判（inconclusive）**，**不得**记为 ③

按**取数前写死的纪律**（`GFIBHEX-PROBE-HANDOFF.md §3`，"③ 的 0 必须附活性反证"）：
- **活性反证缺失**（其它 pid 的 `ATTRDBG-GFIBHEX` 行数 = 0、hit 计数 = 0）；
- ⇒ 无法区分两种情形：**(A)** 本轮确实没有任何进程按名调用 `GetFileInformationByHandleEx`；**(B)** 该目标在这些进程里**根本没有 IAT 站点**（只有 `GetProcAddress`/延迟导入才可达）⇒ 钩子从未被安装，计数自然为 0。
- 后一种与 shim 自身注释一致（`ws_hook.c` 安装期 dump 的注释："a hit count of 0 means no loaded module imported it — it is then only reachable through GetProcAddress"）。

**因此本轮的 0 不是有效否定**；本 Stage 记 **`inconclusive（缺活性反证）`**，不计入排除链。
