## 3. node 进程（pid 7272）· 逐行证据

`node` 探针结果：`existsSync=false`、`stat=ERR:ENOENT`、`lstat=ERR:ENOENT`、**`read="COUNT-FIXTURE"`（成功）**、`readdir=["count-fixture.txt"]`。

同一进程 `shim.log` 序列（行号取自 `shim.log`）：

```
[25161] [7272][320] read-branch resolved flags=0x4  mapped=…\13d-count-probe\query-probe2.mjs
[25162] [7272][321] read-branch real-open ok=1 err=0
[25164] [7272][323] read-branch resolved flags=0x11 mapped=…\13d-stage0\staged\fs\C\…count-fixture.txt   ← 暂存路径 → overlay
[25165] [7272][324] CreateFile overlay(read) …count-fixture.txt
[25166] [7272][325] read-branch resolved flags=0x4  mapped=…\13d-count-probe\ps-seed.ps1
[25167] [7272][326] read-branch real-open ok=1 err=0
[25168] [7272][327] read-branch resolved flags=0x11 mapped=…staged\fs\C\…count-fixture.txt            ← 又一次 overlay
[25169] [7272][328] CreateFile overlay(read) …count-fixture.txt
[25170] [7272][329] R11-D-13d hit CreateFileW n=9
[25171] [7272][330] R11-D-13d hit GetFileAttributesW n=2
[25172] [7272][331] R11-D-13d hit NtSetInformationFile n=1
```

**可下的结论**：
1. node 对**暂存路径**确实走到了 shim 的 `CreateFileW` overlay 分支（`flags=0x11`，两次），且 `readFileSync` 成功 ⇒ 读路径由 `CreateFileW` 钩子服务。
2. node 的 `existsSync/statSync/lstatSync` 失败时，**它自己的进程里 `GetFileAttributesExW` = 0、`NtOpenFile` = 0** ⇒ 这两个入口**不是** node 的 stat/exists 路径。
3. `GetFileAttributesW` 在 node 进程里只被调用 **2 次**；日志里**没有**任何针对 `count-fixture.txt` 的属性解析行（只有 `CreateFileW` 的 `read-branch` 痕迹）。

**必须写明的不确定（不许多跨一步）**：计数是**按入口、不带路径**的 ⇒ 那 2 次 `GetFileAttributesW` **是否针对暂存路径**，现有证据**不能判定**。两种可能仍并存：
- (a) 它们与暂存路径无关（node 查自己的脚本/真实文件），失败路径走的是**未挂钩**入口（`GetFileInformationByHandle`/`NtQueryInformationFile` 一族，v2 **不覆盖**）；
- (b) 它们就是暂存路径，且 `ws_GetFileAttributesW` 的**路径解析/白名单没命中**（Lead 的 §6.4 假设）。
**下一步只需补一个点即可定案**：给属性路径加**一行路径日志**（与 `read-branch resolved …` 同款），或对 `GetFileAttributesW` 包装打印入参路径后复跑同一探针 —— 不改变语义、只加日志。
