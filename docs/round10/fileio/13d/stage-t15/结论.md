## 2. 真身 / 包装 的取法（本轮方法学要点，Lead 已署名采纳）

1. **真身**：手写 **PE 导出目录解析**——`base + DataDirectory[IMAGE_DIRECTORY_ENTRY_EXPORT]` → `IMAGE_EXPORT_DIRECTORY` → 名字/序号表 → `AddressOfFunctions`，**完全不经过 `GetProcAddress`** ⇒ 被挂钩的解析器**无法说谎**。
2. **包装**：运行期**本进程 IAT 槽的实际值**（遍历自身导入表 `OriginalFirstThunk`/`FirstThunk` 读槽内容；与 PE 真身不同者为包装），或 `GetProcAddress(ntdll,"NtQueryInformationByName")` 的返回值。
3. 断言只判"指针 ∈ {真身, 包装, NULL, 其它}"；`LastError` 从不参与判据（D88）。

## 5. 更正（文档级，Lead/exe 复核发现）

我一处计数口径有误并撤回：**"`ATTRDBG-NQIFBN` 16 行、含 `6372×1`（canary）"是假阳性**。
根因：`[winstage-shim][6372][1033] ATTRDBG-CFW … path=…\staged\evidence\attrdbg-nqifbn.txt` 是**进程 6372 写证据文件**的 CreateFileW 行；而 PowerShell `Select-String` **默认大小写不敏感**，文件名 `attrdbg-nqifbn.txt` 被模式 `ATTRDBG-NQIFBN` 命中。
**冻结件逐字计数（更正后）**：真行 **15 条 = 9732×3 / 1644×3 / 9460×3 / 9548×6**，**无 `pid=6372`**（与 `exe` 独立计数一致）。结论不受影响，活性由那四组承担。
纪律沉淀：**计数类 grep 必须 `-CaseSensitive`（或正则同时锚定 `pid=`/`api=` 字段）**，否则"证据文件名"会把自身统计进去。
