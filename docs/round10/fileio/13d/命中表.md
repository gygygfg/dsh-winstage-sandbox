# R11-D-13d 命中/未命中表（**状态：not-run**）

> **本表不是"全未命中"。** 测量从未产生有效读数，**每个入口的状态都是 `not-run`**，缺的是**测量**而不是"命中"。
> 依据与原始证据：[count-window-evidence/README.md](count-window-evidence/README.md)。
> 禁止把本表读成"libuv 不走这些入口"——那条结论**目前没有数据支持**（也**没有被否证**）。

## 0. 为什么是 not-run（两句话）

1. **候选破坏载体**：把计数候选注入 `powershell.exe` 后，**载体自身 CLR 初始化崩溃**（`0xFFFF0000` / `HRESULT 80004005`，**3/3 可复现**）⇒ executor **fail-closed 回退 T1**（无 overlay）。
   A/B 对照：同命令换用在用件 `02C7418F…` 得 `tierEffective=TS` ✅ ⇒ **候选特有**。
2. **dump 被抑制**：`ws_count_dump()` 位于 `DllMain(DLL_PROCESS_DETACH)` 的 `if (!lpvReserved …)` 分支内，而**进程终止时 `lpvReserved != NULL`** ⇒ 正常退出永不 dump。三份日志 `R11-D-13d hit` 行 = 0，且**无 `R11-D-13d` 字样**。

## 3. 取到有效读数前，本表不得被引用为结论

需要的最小修复（详见 [13d-count-patch.md](13d-count-patch.md) §6.1）：
① pass-through 包装**不得 fail-closed**（原指针为空就不安装该目标 / 按模块解析）；② dump 覆盖 `lpvReserved != NULL` 分支。
建议第一版**只给已挂钩入口加计数**（零新增钩子），先拿到安全的那半张表。
