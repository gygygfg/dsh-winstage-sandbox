## 2. 判定：**③ 次数与动作数不符**

探针在夹具上执行 **三个**存在性/属性动作：`existsSync` → `statSync` → `lstatSync`，然后 `readFileSync`。
实测夹具相关的**已挂钩调用只有两次**：**1 次 `GetFileAttributesW`（seq=7）+ 1 次 `CreateFileW`（seq=8）**。
`CreateFileW(0x120089)` 对应 **`readFileSync`（成功）**；而 `NTQIF` 的 3 次**全在脚本句柄 `0x2F0`** 上，**与夹具无关**。
⇒ **三个存在性/属性动作里最多只有一次落到已挂钩 `GetFileAttributesW`，其余没有产生任何已挂钩调用** ⇒ 按预登记表 **③ 成立**（"`seq` 行存在但次数/顺序与动作序列对不上"）。

**与 Stage-name 的交叉印证**：那一轮唯一的 `W` 调用 **成功**（`rc=0 / mapped→overlay / attrs=0x20 / err=0`）。
⇒ 因此最自洽的解释是：**`existsSync/statSync/lstatSync` 的多数（至少两个）走的是未挂钩入口**；那次成功的 `W` 最多服务其中一个动作 ⇒ **"read 通、stat/exists 不通"得到解释**：读走已挂钩并被 overlay 服务的 `CreateFileW`，存在性判定走**我们未覆盖的入口**。

- **③ 成立**（次数不符）⇒ 本 Stage 判定"**调用未按动作逐一产生**"；
