## M4 报错可诊断性

| 项 | 值 |
|---|---|
| 定义 | 用户遇到"没生效/被拒绝"时，界面与宿主侧给出的错误是否含**可操作**信息 |
| 采集方法 | 构造失败并抄录逐字错误，标注：有无错误码、有无原因、有无出路 |
| 判据 | 三类都有"原因 + 出路" = 优；只有原因 = 可；只有"失败/没反应" = 差 |
| **实测：三类** | ① **设置写回失败** → `写入失败，已保留原值`：**无码、无因、无出路**（`05-switch-off-after.png`）。<br>② **可信性告警** → `可信性：⚠ 会话工作根已不可用：写入会失败，不会静默改写真实文件`：有"后果"但**方向与事实相反**（写入其实成功了），无出路（`14-t1-trust-copy.txt`）。<br>③ **批准/拒绝成功路径** → `已终结 1 个候选（真实工作区未被改动）`：**说得很清楚** ⇒ 说明该仓库有能力写清，缺的是把同一标准用到失败面（`13-after-reject-copy.txt`）。<br>**判定 = 差（1/5 → 改进项 I-1 / I-3 / I-4）**。另外：`rowFailed: 此条失败：{message}`、`commandTimeout`、`baselineStaleTitle`（含 rebase 出路）三条文案本轮**未触发** ⇒ `not-run`。 |
