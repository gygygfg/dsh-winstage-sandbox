## 2. 三条跨域阻断链（本轮最有价值的发现）

### 链 A · `dsh-host` 常量暂存根被旧会话占用 ⇒ 新宿主静默没有 fs 面

`review-service.mjs:229` 的默认暂存根是不带会话身份的常量 `dsh-host`；3080 宿主（PID 7812）里的
**旧会话 keeper（PID 9284，`startedAt 21:17`）仍持有它** ⇒ 任何新起、无会话身份的宿主 `StageGuardUnavailableError`
⇒ `winstage-fs` 不激活 ⇒ **线程没有文件工具，进程照样 exit 0**（D2"loader 只 warn 不报错"放大了它）。
绕行：钉 `WINSTAGE_STAGE_ROOT`（配方默认已钉）。

### 链 B · Windows Defender 隔离注入器 ⇒ 静默降级 `tier=T1`（已修 F3）

`shim/out/winstage-inject.exe` 于 **22:31:10 / 22:31:25** 被 Defender 判为 `Trojan:Win32/Bearfoos.B!ml`
（ThreatID 2147731849）并隔离；根因是**仓库根迁移漏迁 Defender 排除项**（排除项仍指已删除的旧根 `…\Desktop\WinStageSandbox`，
历史 10-03/10-04/10-06 同形复发）。注入器缺失 ⇒ CLI 掉 `tier=T1 / enforcement=partial`，
写入语义从"进暂存"变成"内核硬拒"（只有 `sandbox-lane.json` 显形）。
**已修**：加排除（本仓根 / `%LOCALAPPDATA%\Temp\winstage-stage` / 进程 `winstage-inject.exe`）+ 从归档恢复
（sha256 `07FE55DD…518F` == `docs/evidence/MANIFEST.sha256.txt`）。复核者确认 **22:52 之后 0 条新隔离事件**。
**如实声明**：这是加宽 AV 排除面的机器级妥协（耐久解是代码签名）；回滚命令见 `docs/round10/LEAD-修复记录.md` §F3。
**降级路径本身是 fail-closed**（env-harness 实测：写类/不可判定命令被 `STAGING_WRITE_UNVERIFIED` 拒；只读命令按 BUG-4 放行并记账）。

### 链 C · D-SHIM-1：注入后 PowerShell 崩溃 20–28%（**已修**：28/100 → 0/100；代价见 §4.3）

- 崩溃率：**注入 6/30 = 20%、28/100 = 28%**；**不注入（`--direct`）对照 40 次 = 0/40** ⇒ 归因确定在 shim。
- 形态：`0xe0434352`×18、注入器超时 `exit=null`×7、`0xc0000005`×2、`0xffff0000`×1；失败运行统一出现 `STUCK waiting on lock hook`。
- 死亡点：几乎全部停在 CLR 读程序集那一刻（`read-branch resolved flags=0x4 mapped=<.NET 程序集>` 且无配对 `real-open`），
  ⇒ 在 `g_orig.CreateFileW` 之内/紧后，**不是 AMSI 特有**。
- 机制：`ws_hook.c:693-727` 钩住 `LoadLibraryW/A/ExW/ExA`，每次真实加载返回后**同步**调用
  `ws_hook_refresh()→ws_patch_all()`（**全量**重扫改写所有模块 IAT），全程持 `g_hookLock` ⇒ 与 CLR 并发初始化竞争。
- 影响：`delete-capture` 的 `whiteout:V3-*`、`registry-guard` 的 `E8.carrier-powershell` 等"看似无关"的红都是它。
- 修复方向（需改 C + 重建 DLL，Lead 已授权一次限时尝试，见 §4.3）：只补丁刚加载的 `HMODULE` / refresh 移出 LoadLibrary 钩子 / `LdrLockLoaderLock` 串行化。
