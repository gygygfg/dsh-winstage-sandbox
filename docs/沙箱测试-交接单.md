## 2. 另一个线程的启动配方（关键）

沙箱开关是**进程级**的，且**不能设成 User/Machine 级**（那会把本线程和沙箱线程一起绑死）。

**沙箱测试线程（要开沙箱）：**

```powershell
$env:WINSTAGE_SHELL = '1'     # 强制 WinStage 接管，可越过 profile 里的 enabled: false
dsh web --port 3091           # 端口避开 3080/3090
```

**本线程（保持关沙箱，勿改）：**

```powershell
$env:WINSTAGE_SHELL = '0'     # 进程级；随宿主启动注入即可，不要持久化
dsh rescue --port 3090
```

### 为什么必须这样

门控表达式（`dsh-plugin/cordis.patch.yml:122` / `:155`）读的是
`$DSH_HOME/profiles/$DSH_PROFILE/cordis.patch.yml`：

- `WINSTAGE_SHELL=0` ⇒ 强制交还平台 shell（最高优先级）
- `WINSTAGE_SHELL=1` ⇒ 强制 WinStage 接管（可越过"开关关"）
- 否则 ⇒ 读 profile 开关；**读不出（文件缺失/正则不匹配）= fail-safe 判为"开"**

推论（实测）：

- `profiles\web` 里写着 `enabled: false` ⇒ 想要沙箱必须 `WINSTAGE_SHELL=1`。
- `profiles\rescue` 里**根本没有** `winstage-sandbox` 块 ⇒ 门控 fail-safe 判 ON，
  但 **rescue 的 bundles 不含 `dsh-winstage-sandbox`** ⇒ 沙箱行根本不存在
  ⇒ **rescue 永远跑不了沙箱**。所以沙箱线程必须用 `web`（或任何含该 bundle 的 profile）。
- 行级 `disabled` **只在加载期求值一次** ⇒ 改开关必须重启宿主。
