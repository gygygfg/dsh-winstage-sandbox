## 1. 判定链（谁决定什么）

```
src/capability.mjs::probe({root, cacheDir})
  ├─ probeWin32Abi()                      → checks.createRestrictedTokenViable / jobObject
  ├─ probeAppContainer()                  → appContainer.status（只说明"profile 能建"）
  ├─ resolveAppContainerIsolation(...)    → {status, isolation?}
  │     ├─ planAppContainerIsolationProbe()      纯决策：skip / use-cache / measure
  │     ├─ measureAppContainerIsolation()        真跑：建 profile、icacls 授权、起 2 个子进程
  │     └─ assessAppContainerIsolation()         五项判据，缺一即 false（唯一判据源）
  │  ⇒ report.appContainerIsolation = isolation | undefined（**没测出来就保持 undefined**）
  └─ selectTier(report)                   → report.tier = {tier, name, reasons, nesting, t0Gate}

src/executor.mjs::WindowsStageExecutor
  options.tier ──(init)──▶ selectLaunchMode(requested, transparentProbe)
                             T0        → launchMode='appcontainer'  ⇒ createAppContainerLauncher()
                             TS/auto   → 探测通过则 'shim'，否则 fail-closed 回 'restricted-token'
                             其它      → 'restricted-token'（T1）
```

**硬规则（不得违反）**

1. `selectTier()` 的 T0 闸门**只**认 `report.appContainerIsolation?.proven === true`（严格比较）。
   不读缓存时间、不读开关、不读 `appContainerProbe.status` —— 那些说的是"这次跑没跑"。
   `[实测]` 断言：`proven:'true'`（字符串）⇒ 仍 `T1`；报告里放 `appContainerProbe.isolation.proven=true` 也不影响。
2. `report.appContainerIsolation` **不得**被写成 `{proven:false}` 占位：`undefined`（没测）与
   `false`（测了没过）在报告里必须可区分，处置也不同（前者看 `appContainerProbe.reason`）。
3. `options.tier==='T0'` 且 AppContainer 启动路径装配失败 ⇒ `SANDBOX_UNAVAILABLE`，
   **绝不降级成 T1 继续跑**（否则调用方以为在 T0 里，实际只是普通进程）。
4. 通道选择（`launchMode`）与"隔离是否被证明"是**两件事**：前者是执行路径，后者是证据。
   把 `proven` 当成"允许 shim"之类的输入，就是把证据当开关用。

## 2. T0 执行器调用契约（现已实现，T1 拥有）

### 2.1 构造

```js
const executor = new WindowsStageExecutor({
  stagingRoot,            // 必填：唯一可写根（T0 下必须显式授权给包 SID）
  workspaceRoot,          // 逻辑工作区（用于路径还原）
  sessionId,
  mode: 'workspace-write',// 或 'read-only'
  tier: 'T0',             // ★ 只有显式 'T0' 才走 AppContainer
  capabilities: [],       // ★ 能力集**策略层白名单**：默认空 ⇒ 不声明 internetClient ⇒ 网络默认阻断
  profileName: '…',       // 可选：AppContainer profile 名（不传则生成 dsh.stage.t0.<ts><rand>）
  tempDir,                // 可选：私有 temp（也会被授权给包 SID）
})
```

- `capabilities` **不能由调用方随手传**：声明 `internetClient` 就等于开网。
  策略层必须白名单化（README §5.1 的补注）。
- T0 下 `grantPaths = [stagingRoot, tempDir]`（`executor.mjs:1545`），
  授权形式 `icacls <dir> /grant *<包SID>:(OI)(CI)M`（`grantPathToAppContainerSid`）。

### 2.2 生命周期

| 调用 | 契约 |
|---|---|
| `await init()` | 装配 profile + 属性列表 + Job；T0 失败抛 `SANDBOX_UNAVAILABLE`；返回 `initReport` |
| `await run({command, args, cwd, logicalCwd, timeoutMs, env})` | T0 走 `AppContainerLauncher.launch()`：`CREATE_SUSPENDED` → Job → `beforeResume`(shim) → `ResumeThread` → 边等边排水 → 退出码。返回形状与 T1 相同 |
| `dispose()` | 逆序回收：撤销包 SID 授权 → 删 profile → 归还句柄/Job；幂等 |

`initReport` 里与 T0 相关的字段：`tier / tierRequested / tierEffective / launchMode / fallbackReason /
appContainer.{profileName, sid, createdProfile, grants[], attributeListSize}`。

### 2.3 T0 与 T1 的三处不可复用（`[实测]`/`[引用]`）

1. **不能用 `spawnPipedProcess`**：它硬编码 `cb:104`（`sizeof(STARTUPINFOW)`）与 `creationFlags=0`，
   `CreateProcess` 会**静默忽略 `lpAttributeList`** ⇒ 进程起来了但不在 AppContainer 里。
2. **stdio 必须可继承**：`bInheritHandles=false` 拿不到输出；`bInheritHandles=true` + 附着父控制台
   ⇒ 子进程 `0xC0000142`。现方案 = `inheritHandles=true` + `CREATE_NEW_CONSOLE` + 可继承匿名管道，
   且 stdout/stderr **合并为一条流**（本机实测无法分路，诚实记录在 `lastLaunch.streamsSeparable=false`）。
3. **`SECURITY_CAPABILITIES.cbSize` 必须 24**（不是 32）。

## 3. 精确补丁（按需由对应 owner 落地）

### P1 ✅ 已落地（T1）：`icaclsRun` 改文件描述符重定向

**为什么必须**：`[实测]` 本会话（DSH file sandbox）下命名管道捕获子进程输出被拒：
`pipe=false fd=true`（`tests/appcontainer-runtime.mjs` §13 前置探针）。旧实现
`execFileSync('icacls', args, {stdio:['ignore','pipe','pipe']})` 因此**恒返回**
`{ok:false, detail:'EPERM spawnSync icacls EPERM'}` ⇒ T0 的 ACL 授权路径不可用。
T1 已改为 `runCapturedToFiles`（fd 重定向 + 失败退回管道并记原因）。**本条无需再改**，
保留在此是为了记住"输出捕获方式"本身也是一条机制边界（README R10 的同类）。

### P2 ❌ 未落地：让 `probe()` 的档位真的被用上

现状（`[引用]`）：

- `src/cli.mjs:191` `new WindowsStageExecutor({ …, tier: flags.tier })` —— `--tier` 未给即 `undefined`，
  执行器内部 `options.tier ?? process.env.WINSTAGE_TIER ?? 'T1'` ⇒ **默认永远 T1**。
- `dsh-plugin/shell-executor.mjs:468` `this.tier = stringOption(raw, 'tier') ?? 'T1'` —— 同样默认 T1。

补丁（示意，需各自 owner 复核；**不要**在 `proven!==true` 时硬开 T0）：

```diff
 // src/cli.mjs（exec 分支）
+const capability = probe({ root: workspaceRoot, cacheDir: resolve(workspaceRoot, '.dshstage', 'cache') })
+const resolvedTier = flags.tier ?? capability.tier?.tier ?? 'T1'
 const executor = new WindowsStageExecutor({
   stagingRoot: workspace.store.stagedDir,
   mode: flags['read-only'] === true ? 'read-only' : 'workspace-write',
-  tier: flags.tier,
+  tier: resolvedTier,
 })
```

```diff
 // dsh-plugin/shell-executor.mjs（构造期或首次 execute 时）
-this.tier = stringOption(raw, 'tier') ?? 'T1'
+this.tier = stringOption(raw, 'tier')                     // 显式配置优先
+  ?? capabilityReport?.tier?.tier                          // ★ 真实探测结果（proven 才能是 T0）
+  ?? 'T1'
```

要求：`capabilityReport` 必须来自**同一进程内**的 `probe()`（`ProbeVersion=2`、含
`appContainerIsolation`）；探针探测不到就保持 `T1`（fail-closed），**不得**因为"想要 T0"而绕过。

### P3 ✅ 已落地（T1）：`beforeResume` 注入点

```js
launch({ command, args, cwd, job, timeoutMs, env, beforeResume })
// 顺序：runtime.spawn(CREATE_SUSPENDED) → [Job 归属] → beforeResume({pid, process, thread}) → ResumeThread
```

- 未提供 `beforeResume` 时行为**逐字不变**；回调抛错走既有 catch（`TerminateProcess` + 归还句柄）。
- 这解决了 T0 与 T4 shim 的对接形状：**必须**"先建进程、注入、再恢复"。

### P4 ✅ 已落地（T1）：`grantPaths` 支持 `{path, rights}`

shim DLL 所在目录必须授权为**读+执行**（`*<sid>:(OI)(CI)RX`），否则注入在
**用户态初始化阶段**表现为"找不到模块"（不是权限错误，极难归因）。
默认仍是 `'M'`（`grantPathToAppContainerSid` 语义不变），`revokeGrants()` 不受影响。

## 4. 与 T4 的 shim 接口（T0 档位）

**AppInit_DLLs 路线对 AppContainer 无效**（该机制只对普通用户会话生效，且需要写宿主注册表）。
T0 下只有一条路：`CREATE_SUSPENDED` + 远端 `LoadLibraryW` + `ResumeThread`。契约：

| 项 | 约定 |
|---|---|
| 注入时机 | `beforeResume({pid, process, thread})`（进程已挂起，尚未执行用户代码） |
| 注入器 | T4 的 `winstage-inject.exe`（`shim/out/`；注入器自身在宿主侧运行） |
| DLL 可见性 | shim 目录必须进 `grantPaths` 且 rights=`RX`（P4）；DLL 依赖（如有）同理 |
| 失败语义 | 注入失败 = **抛错**（fail-closed）⇒ 执行器终止子进程并报 `runner-failure`；**绝不**恢复进程后继续 |
| 报告 | `initReport.appContainer.grants[]` 必须包含 shim 目录那条授权（含 rights 与 icacls 原始文本） |
| 与 TS/shim 档的关系 | `TS/auto` 档走的是**另一条** `ShimLauncher` 路径（普通令牌 + IAT hook）；两条路径不得混用同一子进程（AppContainer 用包 SID 做访问检查，WRITELIMITED 用受限 SID 交集） |
