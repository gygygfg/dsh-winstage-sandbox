# Agent 沙箱暂存—提交架构设计手册 v3.0

> 统一工作区 · 运行时边界 · 失败教训

---

## 版本说明

本手册是《Agent 沙箱 dry-run 与 commit 架构设计 v2.3（跨平台版）》的继任版本。

v2.3 给出一套「暂存—审批—提交」的硬边界规范，但它写的是**应当是什么**；
实践中经过 182 个会话、两轮真机（Ubuntu 26.04 + Windows 10）与多轮红队审计，
系统在「应当是什么」与「实际会发生什么」之间踩出了大量真实的坑。

v3.0 的变化：

1. 保留 v2.3 的第 1–16 节硬边界骨架，逐条作为本手册第 1–17 章的规范正文。
2. 每一章末尾新增 **「失败教训」** 小节，把历史中真实翻过的车按
   `症状 / 根因 / 修复 / 教训` 四段固化为可检索条目。
3. 新增第 16 章「读取面收敛」，因为历史里信息泄露是出现频率最高、修复最反复的一类问题。
4. 新增附录 A–D：速查表、失败模式分类、验证记录沿革、术语与证据分层。
5. 对 v2.3 中已被实测证伪、不能写成通用规范的说法（例如「tmpfs 一律不能作 lower」
   「userns 与 overlay 一律互斥」）在正文显式降级为**部署实测结论**并附证据。

本手册仍不包含实现代码，只描述契约、边界与教训。

## 第 0 章 证据分层与手册使用方法

### 0.1 证据等级

任何结论必须标注来源，禁止把历史环境的结论直接标为当前验证结果：

| 标记 | 含义 | 例 |
|---|---|---|
| `[实测]` | 在当前目标环境实际执行并观测到的结果 | 本机 bwrap 0.x 挂 overlay 报 EINVAL |
| `[官方]` | 内核/工具/语言官方文档的机制说明 | OverlayFS whiteout 语义 |
| `[报告]` | 用户报告或审计报告，未独立复现 | “/etc/shadow 可读” |
| `[推断]` | 由机制推导但未经本环境验证 | 某后端理论上支持某隔离 |

### 0.2 三类常见误判

1. **环境漂移**：结论来自旧安装副本或旧内核，却当作当前结论。
   历史案例：用户报错路径指向 `/root/.config/nvim/pack/local/opt/NeoAI`，
   说明跑的是安装目录里的旧副本，仓库当前实现已不同。[H:5311]
2. **能力探测与真实执行路径不一致**：探测通过不代表真实路径能成功（见第 5 章）。
3. **测试伪故障**：断言吞异常、套件污染、并行抖动会被误读为产品失败（见第 17 章）。

### 0.3 手册用法

- 做设计：按章节顺序读「规范正文」，它是不变量。
- 做实现：先看该章「失败教训」，大部分坑已经有前车之鉴。
- 做排障：直接查附录 A 速查表，由症状反查根因。
- 做验收：用第 17 章「保证覆盖」而非测试数量。

### 失败教训

> **#0.1 用旧副本下结论**
> 症状：按用户贴的报错路径去排查，结论与仓库当前实现对不上。
> 根因：运行的是安装目录里的旧副本，而非当前仓库。
> 修复：测试环境必须记录实际加载路径、版本、配置、cwd。
> 教训：**先确认跑的是哪份代码，再谈结论。**

> **#0.2 历史环境的结论冒充当前验证**
> 症状：把别处环境的探测结果当成当前环境的保证。
> 根因：未做证据分层。
> 修复：所有结论带 `[实测]/[官方]/[报告]/[推断]` 标记。
> 教训：**机制说明不等于本部署可用。**

## 第 1 章 核心不变量

### 1.1 不变量清单

1. **统一视图**：同一工作区分支内，文件编辑、读取、目录查询、搜索、Git、命令执行与
   语言服务必须读取同一个明确版本的逻辑工作区。
2. **连续修改**：一次工具调用结束只结束该次执行尝试，不清空工作区修改；
   后续调用基于已接受的最新暂存版本继续工作。
3. **删除权威性**：删除是持久化的逻辑状态，不能通过回退读取宿主文件而复活。
4. **资源归属**：每份暂存、候选、缓存、挂载、后台进程、授权和回执必须有明确所有者与生命周期。
5. **继承资源最小化**：沙箱启动前必须限制继承的文件描述符、Windows 句柄、环境变量、
   身份权限及通信入口。
6. **读取也受授权**：宿主文件只读不代表允许读取；路径遮蔽和输出脱敏不能替代输入范围限制。
7. **能力不足不能靠确认补齐**：用户可以批准策略允许的权限扩展，但不能确认一个后端实际
   无法强制执行的安全保证。
8. **表示与权限分离**：路径还原、密钥占位符和界面隐藏只改变表示，不构成隔离边界。
9. **证据分层**：明确区分用户报告、官方机制说明、当前环境实测和推断。

### 1.2 不变量之间的优先级

- 安全边界（5、6、7）> 视图一致性（1、2、3）> 用户体验（第 15 章）。
- 当一致性无法保证时，**拒绝发布**优于产生错误候选（见第 7 章删除缺口）。
- 当隔离能力不足时，**拒绝任务**优于绑定真实工作区为可写（见第 5 章后端降级）。

### 失败教训

> **#1.1 只读声明被当成隔离边界**
> 症状：设了 `read_only` 就以为安全，实际进程内工具仍能读到宿主敏感文件。
> 根因：把「表示（只读标记）」与「权限（真实访问控制）」混为一谈。
> 修复：只读必须有执行边界支持（挂载/ACL），进程内读取必须单独校验范围。
> 教训：**只读是声明，遮蔽才是边界。**

> **#1.2 确认弹窗不能补后端能力的缺**
> 症状：后端无法强制阻断的能力，靠用户点「同意」就继续执行。
> 根因：把审批当成了隔离的替代品。
> 修复：后端能力不足时 fail-closed，不接受「用户已确认」。
> 教训：**审批决定「做不做」，隔离决定「能不能」，两者不可互替。**

## 第 2 章 统一工作区服务与信任边界

### 2.1 Workspace Service 的职责

负责基线快照、逻辑路径、文件与目录状态、删除标记、暂存版本、分支和工具结果归并。

| 对象 | 生命周期与职责 |
|---|---|
| workspace / branch | 保存连续修改；跨多次工具调用存在 |
| session | 保存交互与 shell 上下文，引用指定工作区分支 |
| attempt | 一次隔离执行，使用独立私有可写层 |
| candidate revision | 不可变、可审查的工作区产物 |
| operation | 一次发布或外部操作，拥有稳定回执 |
| service instance | LSP 等长驻服务，绑定项目、身份与权限配置 |

每次 attempt 的可写层保持独立，但其输入来自当前工作区版本，而非每次重新复制真实文件。
执行完成后，控制面以工作区版本条件更新归并结果；并发修改不得后写覆盖先写。

### 2.2 两类工具的信任边界

**进程内工具无法依靠给单次函数调用附加 namespace 获得隔离。** 因此：

> 只有经审核、受控的文件操作实现可以作为宿主侧可信工作区服务运行。
> 它必须统一校验读取范围、写入范围、敏感路径和对象类型。
> 会执行仓库代码、第三方插件或不可信解析器的工具，应迁入隔离进程。

参数路径重写只能是兼容适配层，**不能作为任意插件的安全边界**。
LSP、treesitter 和编辑器扩展是否进入可信计算基，必须明确列出。

### 2.3 架构现实（历史结论）

系统实际是**两层**在协作：

| 层 | 覆盖工具 | 隔离手段 | 对 AI 是否透明 |
|---|---|---|---|
| 外部进程层 | `run_command`、Git 等 | bwrap `--unshare-all` + mount namespace + overlay | 天然透明（看到真实路径） |
| 进程内层 | `read_file`/`edit_file`/treesitter/LSP/buffer 写盘 | 用户态暂存映射 + 路径重写 | 需统一投影才对 AI 透明 |

两条线必须通过**同一份 workspace 暂存表**双向互通，否则出现幽灵文件（第 3 章）。

### 失败教训

> **#2.1 给进程内工具套 namespace 是一厢情愿**
> 症状：想「一劳永逸」把整个 nvim 进程放进 mount namespace + overlay。
> 根因：进程启动后才能加 userns；运行中 nvim 无法事后给自己加 namespace；
> LSP 是独立子进程，不共享同一 mount ns 仍读真实文件；工作区可能是网络盘或不支持 overlay。
> 修复：外部进程用 namespace overlay，进程内工具用暂存映射，靠同一 workspace 表互通。
> 教训：**进程内工具没有隔离，只有投影。**

> **#2.2 先动手后对齐抽象，返工**
> 症状：先写了宿主 git 输出叠加暂存 diff 的 `git_view.lua`，被要求统一命名空间后整套删除。
> 根因：未先对齐抽象层。
> 修复：改成 git 在沙箱内执行，复用统一工作区投影。
> 教训：**先对齐抽象，再动手。**

## 第 3 章 统一命名空间：文件、目录与工具互通

### 3.1 统一语义

工作区服务提供文件读取、属性查询、存在性判断、目录枚举、搜索和变更操作的统一语义。

逻辑状态至少区分：

| 状态 | 读取与枚举语义 |
|---|---|
| 基线对象 | 读取固定基线快照 |
| 暂存文件 | 读取当前暂存内容 |
| 暂存目录 | 与基线目录合并，包含新增子项 |
| 删除标记 | 对所有工具表现为不存在 |
| 状态损坏 | 返回明确错误并阻止发布 |

**不能把「暂存副本意外丢失」自动解释为用户删除。**
删除操作必须持久化删除标记；若记录声明文件存在而存储对象缺失，
应进入损坏或恢复状态，禁止回退真实磁盘。

### 3.2 新增约束

- 创建文件前准备受控父目录；父目录的逻辑状态同步更新。
- 支持目录创建、递归删除、重命名、类型替换和父目录合成。
- 暂存路径保留必要的 basename 与扩展名，语言识别优先使用逻辑文件名。
- 正反向路径映射必须幂等，已经暂存的路径不能再次暂存。
- Git 和命令执行直接使用统一工作区投影，避免逐个解析工具文本并拼接暂存差异。
- 命令执行前物化当前工作区版本，执行后只提取相对该输入版本的新增变化。

### 3.3 只读声明的执行边界

不能仅设置 `read_only` 就跳过所有写入检查。
对真正受强制只读约束的任务可省去候选生成；
对于允许私有缓存写入的任务，必须区分缓存变化与工作区产物。

### 失败教训

> **#3.1 `fs.exists` 判目录恒为 false → 幽灵创建/删除**
> 症状：`create_directory` 报「已创建」但 `ls` 看不到；`delete_file` 报「已删除」但文件还在；
> `file_exists` 先后翻转；`list_files` 报「目录不存在」。`[实测]`
> 根因：`workspace_overrides()` 用基于 `filereadable` 的 `fs.exists` 判断暂存是否还在，
> 而它对**目录恒为 false**，于是所有沙箱新建目录被误标为 `deleted`。
> 修复：改为 `fs.exists(...) or vim.fn.isdirectory(...)`。
> 教训：**存在性判断必须区分文件与目录。**

> **#3.2 目录暂存被错误映射并泄露路径**
> 症状：报错里出现 `.../sandbox/sessions/<hash>/...` 映射路径。
> 根因：`candidate.read_path` 对沙箱新建目录返回了暂存路径，wrapper 把 `list_files.path` 改写成它。
> 修复：目录返回 `nil`；wrapper 对错误分支也做路径还原。
> 教训：**目录参数不能当文件参数重写。**

> **#3.3 edit_file 返回沙箱路径**
> 症状：模型看到不存在的路径。
> 根因：门禁把 `filepath` 重写成 `<root>/workspace/<hash>`，工具回传消息带上了暂存路径。
> 修复：结果统一把暂存路径还原为真实路径（含错误、分页、诊断嵌套结构）。
> 教训：**重写路径，也要还原路径；成功失败都要。**

> **#3.4 多次编辑不叠加**
> 症状：后一次编辑覆盖前一次，模型改一个文件两次结果只剩最后一次。
> 根因：每个 tool call 都是新 attempt，每次从真实文件重新复制。
> 修复：引入持久「工作区映射」`real → staged`，同一文件复用最近暂存内容。
> 教训：**连续修改要跨 attempt 存活。**

> **#3.5 新建文件 ENOENT**
> 症状：新建文件写入报 `No such file or directory`。
> 根因：`_base_entry` 只在「复制已存在文件」时 `ensure_dir`，新建分支直接返回暂存路径。
> 修复：无论新建/复制都先建父目录，并在 init 预建会话目录；父目录逻辑状态同步更新。
> 教训：**写文件前先准备受控父目录。**

> **#3.6 read_file 看不到自己的修改**
> 症状：AI 编辑后读回旧内容。
> 根因：read 工具读真实文件。
> 修复：read_file/file_exists 命中暂存映射时读暂存副本。
> 教训：**同一工作区，所有读者看到同一版本。**

> **#3.7 删除态被复活**
> 症状：暂存副本被删后再编辑，又从未变的真实文件复制回来。
> 根因：`delete_file` 删掉暂存副本后 `ws.deleted` 没置位，`read_path` 回退读真实文件。
> 修复：改为「ws 存在即权威，副本缺失=删除」，`finish` 同步 `deleted`。
> 教训：**删除是持久逻辑状态，不能靠真实磁盘回填。**

> **#3.8 同文件多版本堆积**
> 症状：队列里同一文件出现多个待审。
> 根因：未按修订关系取代。
> 修复：同一分支内新候选取代同路径旧待审（`SUPERSEDED`）。
> 教训：**取代要限定在同一分支与明确修订关系内（见第 12 章）。**

> **#3.9 暂存路径无扩展名导致语言识别失败**
> 症状：treesitter 泛化重写时炸，`vim.filetype.match` 失败。
> 根因：暂存路径用 `_hash_key`，无真实 basename。
> 修复：改成 `<hash>/<真实 basename>`；新增 `staged_to_real` 反向映射并全生命周期维护。
> 教训：**暂存路径要保留可识别的文件名语义。**

> **#3.10 二次暂存**
> 症状：buffer 名已是暂存路径时，写盘把暂存路径又当真实路径 stage 一次。
> 根因：`persist_target` 不识别已是暂存路径的输入。
> 修复：`staged_to_real` 反向映射并复用同一副本。
> 教训：**正反向映射必须幂等。**

> **#3.11 目录级一致性只能靠工具叠加暂存视图**
> 症状：新建目录树对 `list_files` 视图错乱，父目录不合成。
> 根因：`list_files` 只看真实 FS，`_merge_list` 不合成父目录。
> 修复：真实目录不存在但沙箱内有内容时按沙箱视图合成，递归补齐各级父目录；
> 非递归补直接子项；`file_exists` 也查沙箱视图。
> 教训：**目录枚举要合并基线目录与新增子项。**

## 第 4 章 结构化返回与路径还原

### 4.1 返回契约

工具返回必须包含：执行状态、退出码或终止原因、结果数据、逻辑路径、观测范围和证据引用。

- 退出码为 0 且没有输出，明确表示「执行完成，无输出」，不能与未执行混淆。
- 目录为空、搜索无匹配、对象不存在、无访问权限和查询失败必须是不同结果。
  「空目录」等文本仅供界面展示，不能作为内部合并协议。
- 路径转换覆盖成功结果、错误、分页提示、诊断位置和嵌套结构。
  结构化路径字段按映射转换；任意文件正文不做无差别字符串替换，以免改坏业务内容。
- 工具面展示逻辑路径，并明确标注其属于暂存视图；
  真实工作区是否已应用通过发布状态表达。

### 失败教训

> **#4.1 只还原成功结果，不还原错误**
> 症状：`read_file` 读已删除暂存副本时报错带暂存路径。
> 根因：wrapper 的错误分支没有做路径还原。
> 修复：read/fs_write/process 三个分支的错误都还原路径；`delete_file` 增加存在性检查。
> 教训：**路径还原要覆盖错误分支。**

> **#4.2 退出码 0 无输出被误读为「没执行」**
> 症状：`echo hello` 之类命令看似没跑。
> 根因：退出 0 且无输出时，界面显示「（无输出）」。
> 修复：明确语义为「执行完成，无输出」。
> 教训：**要区分「完成但无输出」与「未执行」。**

> **#4.3 结果合并的哨兵值被当成内容**
> 症状：把 `(空目录)`、`未找到匹配内容`、`path: 片段`、目录尾 `/` 当普通文本解析。
> 根因：内部合并协议依赖展示文本。
> 修复：对这些哨兵值特判。
> 教训：**空、无匹配、不存在、无权限是四种不同结果。**

## 第 5 章 能力探测 = 真实执行路径验证

### 5.1 探测范围

CapabilityProbe 不再仅报告软件存在、版本号或内核支持项，
而应验证**本次部署能够实际完成的操作**：

- 实际 lower、upper、work 所在文件系统与挂载拓扑
- namespace 与权限上下文
- 运行时版本及参数语法
- 目标 cwd、挂载顺序和安全策略
- 创建、读取、修改、删除、目录变化、候选捕获及清理

缓存键必须绑定相关环境指纹；
**缓存成功也不能替代实例启动后的必要检查。**

### 5.2 后端切换

> overlay 不可用时，可以切换为完整私有副本加受控 bind，
> 但只能在其满足本任务所需的隔离、视图和捕获保证时继续。
> 无法满足时拒绝任务，不允许绑定真实工作区为可写。

### 5.3 关于「一律」的纠偏

「tmpfs 一律不能作为 lower」「userns 与 overlay 一律互斥」不能写入通用规范。
兼容性取决于具体内核、文件系统、挂载选项和权限环境，应记录为部署实测结果。

### 失败教训

> **#5.1 能力探测假阳性：同源临时目录骗过了探测**
> 症状：`run_command` 100% 失败，报
> `bwrap: Can't make overlay mount ... Invalid argument`。`[实测]`
> 根因：探测用 `vim.fn.tempname()` 建 lower/upper/work，三者都落在同一个 tmpfs 上；
> 真实执行时 lower 是真实 cwd（可能是 tmpfs）、upper/work 在 `/root/.cache`（ext4），
> 跨挂载、跨 userns → 内核 EINVAL。探测场景与真实场景不一致。
> 修复：用**真实路径**实测 `overlay_mountable`，失败降级 `--bind` 私有 cwd。
> 教训：**能力探测必须与真实执行路径一致。**

> **#5.2 `/proc/filesystems` 含 overlay 是假阳性**
> 症状：`_probe()` 看到 `/proc/filesystems` 有 overlay 就判可用。
> 根因：文件系统类型存在 ≠ 本 userns 内能挂载。宿主 `/` superblock 属 init userns 时，
> 新建 userns 里挂 overlay 直接失败。
> 修复：功能实测探测；`overlay_reason`/`overlay_diagnosis` 与 `:NeoAISandboxCaps` 诊断。
> 教训：**支持项存在，不代表可执行。**

> **#5.3 overlay 基目录位于被 overlay 的根之内**
> 症状：overlay 挂载 EINVAL（递归重叠）。
> 根因：upper/work 位于 lower 之下。
> 修复：基目录放到 `/dev/shm/NeoAI-sandbox`（在所有可写根之外）。
> 教训：**存储目录不能与被覆盖树递归重叠。**

> **#5.4 无降级路径，失败直接冒泡**
> 症状：`run_command`、`ls`、`pwd`、`echo` 全部 100% 失败。
> 根因：`process_prefix()` 静态决定是否用 overlay，没有「overlay 失败 → bind 私有 cwd」兜底，
> 设计文档承诺的降级从未触发。
> 修复：能力探测 + 真实路径实测，失败即降级。
> 教训：**承诺的降级路径必须有触发条件与测试。**

> **#5.5 `overlay_mountable` 按 `(lower, dev_upper)` 缓存过粗**
> 症状：粗粒度探测与真实路径实测不一致。
> 根因：缓存键不足以区分真实场景。
> 修复：缓存键绑定环境指纹，并补诊断输出；实例启动后仍做必要检查。
> 教训：**缓存成功不等于实例可用。**

## 第 6 章 每次执行只采用一条物化与捕获路径

### 6.1 单一模式原则

每个 attempt 在启动前选定存储模式，此后物化、执行、捕获和清理必须使用同一模式。
**禁止**同时写入 overlay upper 与独立 bind 副本，再以不确定顺序合并。

### 6.2 挂载类别

挂载配置应先生成可校验的目标树，明确以下类别：

| 类别 | 写入与捕获规则 |
|---|---|
| 工作区产物 | 私有可写，纳入候选 |
| 临时目录 | 私有可写，默认不发布 |
| shell 状态 | 会话私有，不进入文件候选 |
| LSP 缓存 | 服务私有，不进入文件候选 |
| 输入与工具链 | 授权范围内只读 |
| 候选、授权与回执存储 | 沙箱不可访问 |
| 敏感对象 | 按对象类型拒绝或遮蔽 |

- 安全遮蔽必须在最终挂载视图中仍然有效；后续挂载不能覆盖它。
- 文件、目录、socket、符号链接分别处理，不能统一套用目录挂载方法。
- 存储目录由受控分配器创建，避免与用户目录重名、与被覆盖树递归重叠。
- 不得把固定 `/dev/shm` 路径作为跨环境要求。
- 捕获排除依据资源归属和挂载清单，不能只按 `.neoai_session`、`.cache` 等文件名过滤，
  否则会误伤用户文件。

### 失败教训

> **#6.1 双物化捕获到旧内容**
> 症状：同时物化到 overlay upper 和 bind，捕获时 bind 用旧内容覆盖 upper 的新内容。
> 根因：没有先选定模式。
> 修复：先选定 `mode`（overlay/bind），只物化/捕获所选层。
> 教训：**一个 attempt 只有一条物化与捕获路径。**

> **#6.2 挂载点污染捕获**
> 症状：shell 状态 bind 到 `/tmp/.neoai_session`，在 overlay upper 生成目录，被当成文件改动冻结。
> 根因：按文件名约定过滤不足以区分「挂载点」与「用户文件」。
> 修复：捕获时按资源归属/挂载清单过滤，而非只按 `.neoai_session`。
> 教训：**排除依据是归属，不是文件名。**

> **#6.3 `--tmpfs` 不能遮蔽文件或 socket**
> 症状：想遮蔽 socket 却挂不上。
> 根因：tmpfs 挂载点必须是目录。
> 修复：遮蔽 socket 用 `--bind /dev/null <path>`，替换成字符设备后 `connect` 才失败；
> 且必须在 `--dev /dev` 之后、overlay/bind 之后。
> 教训：**对象类型不同，遮蔽方法不同。**

> **#6.4 遮蔽顺序决定成败**
> 症状：受控 docker socket 先被 `/dev/null` 遮蔽，无法在档位里放开。
> 根因：mask 早于 overlay/bind 执行。
> 修复：mask 必须晚于 overlay/bind；受控项在档位 `unmask` 里显式放开。
> 教训：**挂载是顺序敏感的。**

> **#6.5 bwrap `--tmpfs` 权限是 0755，不是 1777**
> 症状：`/tmp` 不满足 sticky/world-writable；`--perms 1777` 又是全局的会污染所有自动创建文件。
> 根因：`--tmpfs` 默认权限固定。
> 修复：预先 chmod 01777 的会话私有目录 `--bind` 到 `/tmp`。
> 教训：**临时目录的权限与生命周期要显式构造。**

> **#6.6 `--proc /proc` 之后才能覆盖 `/proc/*`**
> 症状：`/proc/cmdline` 等覆盖顺序错乱。
> 根因：挂载顺序。
> 修复：`--proc /proc` 之后才覆盖；会话私有 `/tmp` bind 必须在基础 tmpfs 之后、
> session shell 的 `/tmp/.s-*` bind 之前。
> 教训：**先建立，再覆盖；顺序写进契约。**

## 第 7 章 删除捕获必须完整

### 7.1 删除语义解码

OverlayFS 的删除表示必须由后端解码为统一删除清单，覆盖：
- whiteout（可采用**字符设备**或带特定扩展属性的**普通文件**，不能只识别 `.wh.*` 名称或单一类型）
- opaque directory 及启用特性对应的目录语义

### 7.2 禁止「尽力而为」

必须删除以下实现许可：

> ~~无权限创建删除标记时静默跳过。~~

应改为：

> 无法正确表达或捕获删除时，当前模式不可用于该任务；
> 切换经过验证的私有副本模式，或终止执行。不得生成遗漏删除项的候选。

私有层中的中间文件若最终不存在，可以不出现在最终 diff 中；
过程观测仍可记录其活动。最终净变化为空，不代表过程没有副作用。

### 失败教训

> **#7.1 `rm` 静默丢失（最严重的功能缺口）**
> 症状：`rm -f keep.txt` 返回成功、无告警，但候选数=0、待审数=0——
> 删除既不落盘也不入待审队列。`[实测，VM 33 条危险命令]`
> 根因：overlayfs 删除在 upper 里表现为**同名 char 设备 whiteout**（不是 `.wh.` 前缀），
> `capture_overlay` 只认 file/directory。
> 修复：识别 whiteout（`char 0:0`）；后续进一步识别带扩展属性的普通文件形式。
> 教训：**删除捕获不能尽力而为，否则用户以为删了、其实没删。**

> **#7.2 `mknod` 在 luv 未暴露**
> 症状：需要在私有层建 whiteout 时 `vim.uv.fs_mknod` 不存在。
> 根因：luv 未暴露 `mknod`。
> 修复：host 侧 `mknod c 0 0` 尽力而为；无权限时**不能静默**，必须按 7.2 语义处理。
> 教训：**能力缺失要让模式失效，而不是默默漏项。**

> **#7.3 物化残留**
> 症状：同一路径先物化后修改/删除会残留旧 upper 内容。
> 根因：写入前未清理目标。
> 修复：先 `delete dest` 再写或建 whiteout。
> 教训：**物化是「替换」不是「追加」。**

> **#7.4 `unshare` 兜底后端无法 bind mount**
> 症状：无法施加 `/proc/sys` 遮蔽，也无法正确表达删除。
> 根因：后端能力不足。
> 修复：对 `process` fail-closed；默认 `require_seccomp=true` 使其不可用。
> 教训：**弱后端不能假装强保证。**

## 第 8 章 启动边界：继承资源、读取面与内核接口

### 8.1 受信启动器

进程启动必须经过受信启动器，显式构造环境与继承资源白名单。

- Linux 关闭或标记关闭所有非授权文件描述符；Windows 使用明确的可继承句柄集合。
- **不以 shell 能否关闭高编号 fd 作为安全保证。** 无法完成继承资源收敛时拒绝启动。
- LSP、Git、下载器和其他后台程序使用相同启动要求。
- 环境从允许清单构建，**禁止依赖「与父环境合并」来删除秘密或代理变量**。
- 删除多余 capabilities、危险 token privileges，同时独立约束实际身份、文件访问和对象权限。

Linux 可使用专门的描述符关闭机制（如 `close_range`）实现该契约，具体兼容方案由后端提供。

### 8.2 系统挂载与内核接口

- 宿主整根只读挂载退出默认方案。运行环境以最小基础镜像、工具链闭包和批准输入构造；
  动态加载器、必要符号链接和运行时资源必须一起验证。
- `/proc`、`/sys` 和设备访问按用途最小开放。
  宿主全局控制接口必须只读或不可达，不能只遮蔽有限的高危文件名。
  删除 capabilities 不能代替这些访问限制。
- socket 地址族、namespace 创建与进入路径纳入独立策略。
- seccomp 能力说明不得声称能够直接解引用任意指针参数。
- 隐藏挂载名称、进程名称或沙箱指纹仅属信息最小化，不作为验收通过依据。

### 失败教训

> **#8.1 fd 继承逃逸（最致命）**
> 症状：spawn `bwrap` 前没关继承 fd，宿主 AppImage 的目录 fd
> `1023 -> /tmp/.mount_*` 被继承，`openat(dir_fd, "..")` 逐级上溯即可回到宿主 `/`，
> 绕过 chroot/命名空间。`[实测]`
> 根因：namespace/chroot 不关继承 fd 形同虚设。
> 修复：优先 `bash`（支持多位数 fd），无 bash 用 `python3 os.closerange`，
> 最后退回 `sh`（仅个位，尽力）；seccomp 的 `exec 3<filter` 必须在关 fd 之后执行；
> LSP 自建 bwrap 前缀也要同样包装。
> 教训：**先关继承 fd，再谈隔离。**

> **#8.2 `/bin/sh` 是 dash，只支持个位数 fd 重定向**
> 症状：`exec 1023>&-` 报 `exec: 1023: not found`，整个命令 exit 127。
> 根因：dash 对 `fd>=10` 的关闭循环全部失效。
> 修复：按 bash → python3 → sh 的顺序降级，并识别降级能力边界。
> 教训：**shell 的 fd 能力差异是暗坑。**

> **#8.3 `jobstart` 的 env 是与父环境合并的**
> 症状：想用 `env` 删除秘密/代理变量，删不掉。
> 根因：`vim.fn.jobstart` 的 `env` 是**合并**语义；`vim.NIL` 会变成字符串 `"v:null"`；
> `""` 对 Python `urllib.getproxies()` 也无效。
> 修复：清代理只能在命令前 `unset`（`runtime.proxy_unset_snippet()`）。
> 衍生坑：网络网关模式注入的代理若照样 `unset` 会删掉网关代理 → 网关启用时跳过 unset。
> 教训：**不要用环境变量删除来实现安全控制。**

> **#8.4 `--cap-drop ALL` 挡不住 `/proc/sys` 写入**
> 症状：以为 cap-drop 后写 `core_pattern` 会被拒，实际能写。`[实测]`
> 根因：全局 sysctl 写权限按 `test_perm` 的 **DAC**（`euid == 全局 root uid`）判定，
> 与 capability 无关。
> 修复：必须用挂载 `--ro-bind /proc/sys /proc/sys` 一次性封闭所有全局 sysctl 写面。
> 教训：**能力（capability）不等于权限（DAC）。**

> **#8.5 `/proc/sys` 是非命名空间的全局状态**
> 症状：`net.*` 在共享 netns 下会直接改宿主网络。
> 根因：全局状态跨 namespace 可见可写。
> 修复：只读绑定，且共享 netns 放行网络时必须声明代价。
> 教训：**全局接口要么只读，要么不可达。**

> **#8.6 `clone` 可绕 `unshare`**
> 症状：denylist 拦了 `unshare`/`setns`，但 `clone(CLONE_NEWUSER)` 仍能建嵌套 userns；
> `clone3` 的 flags 在指针里，经典 seccomp 读不到。
> 根因：只拦系统调用名，不拦 flags。
> 修复：按 flags 过滤命名空间位；`clone3` 返回 `ENOSYS` 让 glibc 回退到 `clone` 再受过滤；
> 不能整块封 `clone`（会打断 fork/线程）；BPF 跳转偏移要精确核对 `jt/jf`。
> 教训：**拦系统调用要拦参数，不是拦名字。**

> **#8.7 `AF_VSOCK` 不受 netns 隔离、也不经代理**
> 症状：以为断网/代理覆盖了一切网络路径。
> 根因：socket 地址族绕过。
> 修复：地址族显式收敛。
> 教训：**网络控制要枚举旁路（裸 TCP/UDP/IPv6/继承 socket/Unix socket/vsock）。**

> **#8.8 审计中的虚惊：`ls -l /proc/self/fd` 的 fd 3**
> 症状：以为又发现一个继承 fd。
> 根因：fd 3 是 `ls` 自己打开的目录 fd。
> 修复：无。
> 教训：**排障先拿原始证据，别急着下结论。**

> **#8.9 `/proc/net` 是 `self/net` 符号链接，无法 tmpfs 遮蔽**
> 症状：bwrap 拒绝 `--tmpfs /proc/net`（`Can't mount on symlink`）。
> 根因：procfs 符号链接挂载限制。
> 修复：记为残余边界并写入文档；不要在这条上过度投入。
> 教训：**有些泄露只能声明为残余，不能假装消除。**

## 第 9 章 网络策略：显式模式

### 9.1 三种模式

| 模式 | 语义与限制 |
|---|---|
| OFFLINE | 强制阻断网络；优先于其他网络配置 |
| CONTROLLED_ONLINE | 在任务授权范围内联网，必须阻断代理绕过与禁止目标 |
| OBSERVED_ONLINE | 提供代理和记录，但存在未被强制覆盖的直连路径 |

- 交互产品可以在任务授权覆盖联网范围与预算时默认采用 CONTROLLED_ONLINE。
- 只有代理环境变量而没有强制出口约束的部署，必须报告 OBSERVED_ONLINE，
  不能显示「本机访问已完全阻断」。
- 要求禁止宿主访问或任意外部写入的任务，不能在能力不足时自动降为 OBSERVED_ONLINE。

### 9.2 网络契约必须明确

- 本机、宿主地址、链路本地地址、云元数据地址及任务禁止的私网范围。
- DNS 解析、实际连接地址与重定向之间的绑定。
- 裸 TCP、UDP、IPv6、继承 socket、Unix socket、vsock 等旁路。
- 租约撤销对存量连接的处理。
- **HTTP 代理只观察 CONNECT 目标时，无法证明加密隧道内没有外部写操作。**
- 代理健康检查必须验证实际应用请求及拒绝行为，不能只验证端口握手。
- 观测记录按 attempt 归属，禁止用全局 drain 方式混合不同命令证据。

若要求 staged execution 不产生真实外部写入，就不能同时向任意程序开放通用互联网连接
并继续声称该保证成立。依赖读取应通过受控下载器；真实外部操作通过 broker 执行并独立授权。

### 失败教训

> **#9.1 纯 Lua 做不了透明拦截**
> 症状：无法拦截裸 TCP 目的地。
> 根因：拿不到 `SO_ORIGINAL_DST`/`IP_TRANSPARENT`/`TPROXY`，`socat` 也不支持 TPROXY；
> 目标地址在 `sockaddr` 指针里。
> 修复：只能做 HTTP 代理网关（裸 TCP 不经代理不生效）；
> 「无 root + 拦裸 TCP + 放行外部」三者不可兼得，必须如实说明。
> 教训：**应用层代理 ≠ 硬边界。**

> **#9.2 宿主防火墙静默丢 veth 流量**
> 症状：`ping` 通但 TCP 超时，误以为网关坏了。
> 根因：ufw 静默丢包。
> 修复：仅对该 veth 接口插 `iptables -I INPUT` 放行，teardown 移除（绑接口名，接口删了即失效）。
> 教训：**先排除宿主防火墙。**

> **#9.3 `vim.fn.system` 阻塞 libuv 事件循环**
> 症状：同步 `nc` 诊断时网关根本无法 accept，造成「网关坏了」的假象。
> 根因：同步调用占住事件循环。
> 修复：异步 `jobstart` + `vim.wait` 才能验证。
> 教训：**验证异步系统，不能用同步调用。**

> **#9.4 `uv.listen` 握手进 backlog 就算成功**
> 症状：`nc -z` 返回 0，误以为应用已 accept。
> 根因：backlog 与 accept 是两回事。
> 修复：用真实 HTTP 请求验证。
> 教训：**端口握手不等于应用可用。**

> **#9.5 Deferred 回调里断言抛错被吞，表现成卡死超时**
> 症状：端到端用例「卡死 30s」，排查方向完全错。
> 根因：`t.matches("403")` 抛错，`done=true` 永不执行。
> 修复：回调内先打印原始结果，`done` 用 pcall 或先置位再断言。
> 教训：**异步断言不能让失败变成超时。**

> **#9.6 探测摘要跨命令泄漏**
> 症状：上一条命令的探测混进下一条。
> 根因：全局 drain。
> 修复：命令开始时先 `drain_probes()`。
> 教训：**证据按 attempt 归属。**

> **#9.7 `_proxy_unset_snippet` 把网关代理解掉**
> 症状：网关启用后代理被 unset，端到端测试失败。
> 根因：代理 strip 与注入代理冲突。
> 修复：启用拦截代理时返回 nil（跳过 unset）。
> 教训：**功能之间会互相拆台，接线要有优先级。**

> **#9.8 `socat + unix socket` 在共享 netns 下是多余的**
> 症状：多一个沙箱内进程与依赖，没增加隔离强度。
> 根因：前提（隔离 netns）变化后方案作废。
> 修复：直接 loopback 代理，监听 `127.0.0.1` 随机端口。
> 教训：**前提变了，旧方案要敢于作废。**

> **#9.9 `ip netns exec` 与 bwrap 的组合**
> 症状：组合后断网/隔离失效。
> 根因：bwrap 又 `--unshare-net`，且前缀顺序错。
> 修复：用 `NO_USER_FLAGS`，前缀放在 seccomp `sh -c "$@"` 之前。
> 教训：**隔离层叠加要显式协调。**

## 第 10 章 秘密处理：展示、执行、发布三阶段

### 10.1 三阶段拆分

密钥占位符不能同时充当脱敏文本、可用凭据和发布内容。

| 阶段 | 规范要求 |
|---|---|
| 展示 | 使用受控占位符与脱敏内容 |
| 执行 | 默认不提供真实秘密；需要认证时使用 broker 或明确授权的专用执行环境 |
| 发布 | 受信服务构造最终字节，验证后冻结，并绑定最终摘要 |

- 如果允许 Agent 编辑含占位符的文件，必须分别保存真实基线摘要、展示视图摘要、
  映射版本及恢复权限。
- 审批必须绑定最终待发布产物，不能在摘要校验后再进行未经绑定的秘密替换。
- 映射丢失、歧义或无法验证时禁止发布，不能把占位符写入真实文件。
- 受保护映射需要支持恢复，并独立鉴权。
- 高熵扫描只作为辅助证据；已知秘密与具名凭据使用明确规则处理。
  不能把「纯 hex 排除」当成完整覆盖，也不能因为测试向量疑似秘密而直接中止整个 Agent。
- 沙箱内不可用的凭据需要结构化说明原因，避免将占位符导致的认证失败误判为服务故障。
- 不得通过日志回显真实凭据来诊断。

### 失败教训

> **#10.1 代码表达式被当成密钥 → 误终止 Agent**
> 症状：`edit_file` 里 `api_key = os.getenv(...)` 触发了 `SANDBOX_SECRET_BLOCKED`。
> 根因：`_apply_secret_names` 把敏感名后的 `os.getenv` 写入密钥映射表，
> 随后 `edit_file` 的 `edits` 含 `os.getenv` 时命中它。
> 修复：新增 `_looks_like_literal_secret`（纯 hex / 含 `+/=:` / 含数字且够长），
> 值后紧跟 `(`（函数调用）直接跳过。
> 教训：**别把代码当密钥。**

> **#10.2 具名规则过度匹配散文**
> 症状：注释里的 “Bearer token” 被当凭据入库，后续误终止。
> 根因：`bearer`/`basic_auth` 规则过宽。
> 修复：规则加 `validate` 钩子，要求凭证足够长且像 token。
> 教训：**规则要校验形态，不是只匹配关键词。**

> **#10.3 纯 hex 密钥逃过熵检测**
> 症状：`exclude_pure_hex=true` 让 `GLM_API_KEY=dfe946…` 原样注入。
> 根因：只看熵，不看变量名。
> 修复：按 env 名（`KEY/TOKEN/SECRET/PASSWORD/CREDENTIAL`）强制 token 化；
> **不能**用太宽的 `AUTH`，否则误伤 `SSH_AUTH_SOCK`。
> 教训：**高熵扫描只是辅助证据。**

> **#10.4 软/硬信号分级**
> 症状：环境变量名/加密 token 被硬终止；原始明文 key 又需要严防。
> 根因：风险不分作用域、不分形态。
> 修复：原始未加密 key（工具参数或 AI 可见上下文）→ 硬拦截并终止；
> 敏感变量名/加密 token（全大写、含敏感段、长度 ≥6）→ 置 `ctx.secret_operation`，
> 合成 `secret_warning`，强制待审但不终止；风险等级按工作区内 L2、工作区外 L3。
> 教训：**秘密处理要分级，不能一刀切。**

> **#10.5 env 分叉导致 401 被误判**
> 症状：沙箱把 key 换成 `NEOKEY_*`，AI 无从判断 → 误判 401。
> 根因：token 化后没有告知 AI 映射关系。
> 修复：注入 `NEOAI_TOKENIZED_ENV` 名单 + `tokenize_env` 开关 + 读取提示；
> 沙箱内不可用的凭据给出结构化原因。
> 教训：**不可用要解释原因，不能伪装成服务故障。**

## 第 11 章 会话与 LSP 生命周期

### 11.1 shell 连续性

shell 连续性仅承诺规范中列出的状态，例如逻辑 cwd 和经过筛选的环境变量。
别名、函数、后台进程、打开的 fd 等**不默认跨命令继承**。

shell 状态属于不可信输入；不能直接把任意保存文本交给宿主 shell 执行。

### 11.2 LSP 分片与缓存

- LSP 按项目、工作区分支和权限配置分片，使用稳定的服务目录。
- 会话轮换时更新其工作区版本引用，不能依赖已被清理的 attempt 挂载。
- LSP 缓存可以独立持久化，但只能映射专用、受限目录，
  禁止为便利暴露整个用户数据目录、keyring 或凭据位置。

> LSP 使用适合其运行时的隔离模板；兼容性例外必须有明确范围与测试，
> 不能整体绕过文件、身份、网络和继承资源约束。

所有编辑器 hook、事件、代理、防火墙规则与后台服务必须支持**幂等卸载**，
恢复被包装接口，并清理本实例拥有的资源。

### 失败教训

> **#11.1 run_command 每次独立 shell**
> 症状：`export`、`cd` 跨命令丢失。
> 根因：每次调用是新 shell。
> 修复：会话目录 bind 到沙箱内固定路径，命令前后保存/载入 cwd + `export -p`。
> 教训：**只承诺规范列出的连续性。**

> **#11.2 跨循环不隔离**
> 症状：工作区映射全局持久，不同 agent 之间混用。
> 根因：只见 attempt，没有会话作用域。
> 修复：会话作用域：循环内共用，agentEnd 轮换并**迁移暂存内容**保证一致性。
> 教训：**资源要有所有者与生命周期。**

> **#11.3 LSP 会写缓存/日志，套进 overlay 会污染候选**
> 症状：LSP 缓存进入待审队列或被清理。
> 根因：没有区分「工作区产物」与「服务私有缓存」。
> 修复：`stdpath(cache|data|state)`、`~/.cache`、`~/.local/*` 以 rw bind 直连宿主。
> 教训：**缓存变化不等于工作区产物。**

> **#11.4 LSP 不能套 seccomp**
> 症状：Node/JIT 等被 seccomp 打断。
> 根因：隔离模板不匹配运行时。
> 修复：LSP 前缀单独构造，不复用 `runtime.process_prefix` 的 seccomp 包装；
> 但文件、身份、网络和继承资源约束不能整体绕过。
> 教训：**兼容性例外要有范围与测试，不是免检。**

> **#11.5 LSP 生命周期跨 agent 会话**
> 症状：agentEnd 轮换后挂载点指向旧目录、refresh 写新目录无效。
> 根因：用会话 `proc_dir` 作 overlay base。
> 修复：使用稳定 base。
> 教训：**长驻服务的引用不能依赖会被清理的短命资源。**

> **#11.6 多项目串扰**
> 症状：共用同一 upper 导致相对路径冲突。
> 根因：未按项目分片。
> 修复：按 cwd hash 分片。
> 教训：**LSP 按项目、分支、权限配置分片。**

> **#11.7 包装 `vim.lsp.rpc.start` 必须可卸载**
> 症状：热重载后残留包装或丢失原函数。
> 根因：不符合「副作用可卸载」约定。
> 修复：`install()` 返回 cleanup，恢复原始函数。
> 教训：**所有包装都要能幂等卸载。**

## 第 12 章 候选与选择性审批

### 12.1 候选完整性

- 候选同时保存可验证的 **before 与 after** 内容或快照引用。
  审批 diff 不得临时读取已变化的真实磁盘作为旧版本。
- 同一路径的新修改，只有在同一工作区分支和明确的修订关系内，才可取代旧待审版本。
  **不能全局按路径 supersede**，因为其他候选可能属于独立分支或仍被依赖。
- 纯文件候选没有净变化时不入队；
  宿主操作、权限变化等不能因「文件数为零」被过滤。

### 12.2 选择性应用

> 用户选择子集后，先生成新的 publication_set 并验证。
> 未选择部分保留为可追踪修订；已选部分发布后，剩余部分根据基线变化进入
> 继续待审、依赖阻塞或 STALE，**不能直接删除整个原候选**。

- 审批计数明确展示「待审文件数」和「宿主操作数」，展开后再展示变更单元及依赖。
- 去重规则和分页统计口径必须固定。
- 跨文件、注册表、服务和防火墙的组合称为**不可拆分审批组**：
  它表示必须整体审查，不能暗示底层执行具备事务原子性。
- 丢弃候选先持久化取消或丢弃状态、解除引用，再回收存储；
  不能先删内容、留下 PENDING 记录。

### 失败教训

> **#12.1 空候选入队（0 个文件）**
> 症状：出现 `edit_file（0 个文件）` 的空待审项。
> 根因：写入内容与基线相同仍冻结候选；`review.enqueue` 不跳过无文件候选。
> 修复：在 enqueue、list、wrapper 三处收口，无实际改动按只读完成处理。
> 教训：**没有净变化就不入队（但仅限纯文件候选）。**

> **#12.2 选择性 apply 吞掉其余文件**
> 症状：用户选一个文件应用，其余文件直接丢失。
> 根因：原 `apply(files=...)` 发布子集后直接 `discard_candidate` 整份候选。
> 修复：`_requeue_remaining` 重新入队，未选部分保留为可追踪修订。
> 教训：**部分应用不能删除整体。**

> **#12.3 陈旧 `CHANGE_SET_NOT_APPROVED`**
> 症状：界面/历史 id 触发 apply 必然失败（`cs_7_…`）。
> 根因：该变更单元已被后续编辑 `SUPERSEDED`，候选已丢弃。
> 修复：`M.apply` 沿 `superseded_by` 链重定向到最新版本，终态 `APPLIED` 幂等返回
> `ALREADY_APPLIED`，并有环路保护。
> 教训：**审批要绑定最终待发布产物，陈旧引用要能重定向。**

> **#12.4 host_op 被「0 文件」逻辑过滤**
> 症状：宿主操作审批项消失。
> 根因：`review.list` 的「过滤 0 文件空项」逻辑误伤 `kind=="host_op"`。
> 修复：特判 `kind=="host_op"`；审批走整条审批分支，不能按文件路径。
> 教训：**宿主操作不能因文件数为零被过滤。**

> **#12.5 丢弃候选不想同步待审项**
> 症状：`:NeoAISandboxDiscard` 后重开聊天，无效待审项又冒出来，应用必 `CANDIDATE_NOT_FOUND`。
> 根因：只删候选文件，`review_state` 仍 `PENDING` 落盘。
> 修复：新增 `discard_by_digest`；丢弃先持久化状态、解除引用，再回收存储。
> 教训：**丢弃是一个有状态的操作，不是删文件。**

> **#12.6 diff 的 before 读真实磁盘**
> 症状：审批 diff 显示错误旧版本。
> 根因：候选只有 after 内容和 `before_hash`，没有 before 内容。
> 修复：候选保存可验证的 before 与 after。
> 教训：**diff 两侧都必须在候选里冻结。**

## 第 13 章 持久化、恢复和清理闭环

### 13.1 恢复

启动与热重载先恢复持久状态，再重建工作区投影和待审列表。
若存在多个分支或相互冲突的候选，应**分别恢复**，不能把全部待审内容平铺到一个目录。

### 13.2 清理顺序

> 逻辑解除引用 → 停止写入者 → 卸载或释放句柄 → 校验归属 → 删除资源 → 记录结果。

- 权限为 `0000` 的内部目录可以由受信清理器修复后删除，
  但必须限定在已验证归属的私有存储树，禁止跟随链接越界或修改用户目录权限。
- 清理失败要记录残留对象、原因、占用预算和重试状态。
  无法收敛写入者时不得冻结候选，也不得复用该资源。
- 控制面、回执、候选和服务缓存分别设置保留规则。
  等待审批、对账或恢复引用的对象不参与普通清理。

### 失败教训

> **#13.1 E484：`work` 子目录 0000 权限导致残留**
> 症状：bwrap 在 overlay workdir 下以 **0000 权限**创建内部 `work` 子目录，
> `vim.fn.delete(dir,"rf")` 进不去 → `E484: Can't open file …/overlay_work/work`，
> 并**残留整个 attempt 目录**（资源泄漏）。`[实测，宿主与 VM 均复现]`
> 根因：清理器没有先修复权限。
> 修复：新增 `_make_removable()`，递归 chmod 目录为 0700（只递归真实子目录、不跟随符号链接）后再删除。
> 教训：**清理前先修复权限，且只作用在已验证归属的私有树。**

> **#13.2 shutdown 清暂存但留待审队列**
> 症状：会话重置/热重载后待审修改「凭空消失」，只读工具看不到。
> 根因：`sandbox.shutdown()` 清空暂存目录，但待审队列仍落盘。
> 修复：`sandbox.init()` 新增 `_rehydrate_pending`，按待审候选内容重新物化进新会话暂存层。
> 教训：**持久状态与投影要一起恢复。**

> **#13.3 `/tmp` 命名空间映射的清理不同步**
> 症状：改成 `<root>/.cache-<tag>/<session>` bind 回根后，宿主 `/tmp` 残留。
> 根因：rotate/reset 的清理没同步。
> 修复：清理路径随映射同步更新。
> 教训：**映射变了，清理也要变。**

> **#13.4 持久化旧数据干扰测试与恢复**
> 症状：用户会话遗留大量 SUPERSEDED 项，测试遍历 `list_reviews()` 拿到别的文件。
> 根因：跨进程残留。
> 修复：测试按目标路径过滤；repro 之间 `sandbox.reset()`。
> 教训：**测试与恢复都要隔离持久状态。**

## 第 14 章 策略语言与 Windows 条款纠偏

### 14.1 策略语言

> Python、JavaScript 与可选 Lua 规则必须运行在受操作系统约束的低权限独立宿主中。
> 语言子集、审计钩子、subinterpreter、Context、Isolate 和原型冻结属于附加防护，
> **不单独满足本规范的执行边界**。

- RestrictedPython 官方明确说明其不是沙箱；PEP 578 也不将审计钩子定义为沙箱。
- Node 官方明确警告 `node:vm` 不是安全机制。
- 跨语言一致性要求适用于同一策略语义的不同实现，应统一整数、空值、路径、排序和时间等语义。
- 不同用途的 Python 与 JS 规则本来可以返回不同判断，最终由聚合器按**拒绝优先**处理。

### 14.2 Windows 条款

- CI、MIC、审计与调用期过滤分别描述，删除「最接近 seccomp」的模糊类比。
- DACL 负责允许与拒绝访问；SACL 中审计项与强制标签相关作用分别表达，
  不能写成两者共同授予写权限。
- `FILE_ID_BOTH_DIR_INFO.FileId` 是 **64 位**字段；需要 128 位身份时采用相应接口与结构。
- 文件身份属于存储定位与证据，不能要求复制后的候选保留原 `FileID`；
  内容摘要与对象身份分开。
- 注册表事务边界由适配器针对具体 API 和操作集声明，
  不能从「位于单 Hive」直接推断全部可回滚。
- TxF 不列入必要发布能力，默认发布与恢复协议不依赖它。

### 失败教训

> **#14.1 Windows ACL 测试脚本自身有 bug**
> 症状：`acl-deny-write=False`，一度以为平台机制失败。
> 根因：安装期脚本以 SYSTEM 运行，`$env:USERNAME` 为空；且读取断言在 SYSTEM 上下文下不稳定。
> 修复：改用 `[System.IO.File]` + 写入前基线对比；免重装注入（`losetup -Pf` + `ntfs-3g -o rw`
> 替换脚本，Startup `.cmd` 重启执行）后复跑全绿。
> 教训：**测试失败先怀疑测试。**

> **#14.2 Windows 真实 VM 验证结果**
> 结果（Win10 Enterprise 10.0.19045，真实 VM）：`[实测]`
> - Job Object `KILL_ON_JOB_CLOSE` + ActiveProcessLimit 进程树回收：**pass**
>   （`assigned=True aliveBefore=True exitedAfterClose=True`）
> - ACL deny ACE 阻止写入且内容不变：**pass**
>   （`acePresent=True writeDenied=True contentUnchanged=True`）
> 教训：**跨平台边界要在真实内核上验证，不能只靠静态分析。**

> **#14.3 noVNC 键盘对 Shift 组合字符映射错误**

> 修复：把命令写进 `/shared/*.sh`，只输入不含 Shift 的简单路径；
> 或用免重装注入脚本文件的方式。
> 教训：**可靠注入用脚本文件，不用键盘模拟。**

## 第 15 章 UI 按状态驱动，重入与重试有界

### 15.1 状态驱动

- 窗口创建、关闭、恢复和异步重试使用明确状态、实例标识与版本校验。

### 失败教训

> **#15.1 恢复输入框 E242**
> 症状：`E242 Can't split a window while closing another`。
> 根因：在 `WinEnter` 自动命令里 `:split`，撞上 telescope 正在关窗口。
> 修复：先同步尝试，失败用 `vim.schedule` 延迟到主循环下一拍，

> **#15.2 延迟恢复变两个输入框**
> 症状：出现两个输入框。
> 根因：`collapsed=false` 放在创建之后，创建窗口同步触发 `WinEnter` 重入又建一个。
> 修复：创建前先置位；已建出窗口则不再重试；同步 `pcall` 失败但窗口已建出视为已恢复。
> 教训：**先占位，再创建。**

> **#15.3 headless 与交互式时序不同**
> 症状：嵌套 `WinEnter` 的 bug 在 headless 复现不了。
> 根因：事件顺序不同。
> 修复：靠逻辑保证 + 单输入框断言兜底，交互侧人工验证。
> 教训：**headless 通过不代表交互通过。**

> **#15.4 折叠「思考过程」匹配过度**
> 症状：所有折叠都渲染「思考过程」。
> 根因：`fold.detect` 对非工具折叠一律回退 `reasoning`。
> 修复：渲染层写入 buffer 后**显式登记推理块起始行**（buffer 弱键表），
> `foldtext` 只对登记行显示思考过程，其余用中性 `📄`。
> 教训：**类型靠元数据，不靠文本猜测。**

> **#15.5 测试用了渲染器根本不会产出的行结构**
> 症状：单独跑失败、全量跑「通过」（别的套件残留 override）。
> 根因：用例伪造了不存在的行结构，且顺序相关。
> 修复：用真实渲染行 + 显式清 override。
> 教训：**测试夹具要真实，且不能依赖前序残留。**

> **#15.6 `nvim_buf_set_lines` 不接受含换行元素**
> 症状：路径/命令含 `\n` 直接 E5108。
> 根因：API 约束。
> 修复：统一 `_one_line` 压单行 + 防御性扫描；展示层转义，原始数据不动。
> 教训：**展示处理不能修改保存的原始数据。**

> **#15.7 审批窗重开与 diff 重入**
> 症状：临时关窗后重开光标丢失；diff 窗 `BufWipeout` 重入 `_close_diff`。
> 根因：关闭逻辑重入。
> 修复：重开恢复光标；先清 state 再关 buffer。
> 教训：**关闭路径要幂等。**

## 第 16 章 读取面收敛（历史高频缺陷）

### 16.1 问题本质

「宿主只读」不等于「允许读取」。
整根只读暴露 + 黑名单遮蔽的组合无法穷尽敏感文件，历史审计反复命中：

| 类别 | 典型泄露 | 证据 |
|---|---|---|
| 账户口令 | `/etc/shadow`、`/etc/gshadow` | `[报告]` |
| 宿主身份 | `/etc/passwd` 真实账户、`/home/*` 真实用户目录、`/root/.bash_history` | `[报告]` |
| 系统指纹 | `/proc/cmdline`（内核版本、`root=UUID`、`crashkernel`）、`/proc/version` | `[实测]` |
| 软件清单 | `/usr/bin`、`/usr/share/doc`（完整包数据库）、`/usr/src`、`/usr/local/go_workspace` | `[实测]` |
| 网络身份 | `/etc/resolv.conf`（Tailscale 域） | `[实测]` |
| 内核信息 | `/proc/kcore`、`/proc/modules`、`/proc/kallsyms`、`/proc/vmallocinfo` | `[实测]` |
| 跨会话残留 | `/tmp`、`/var/tmp` 里的上一会话抓取目录、`NEOKEY_*` 轨迹、dump 配置 | `[实测]` |
| 进程内绕过 | `read_file /proc/self/root/etc/shadow`、`/proc/1/root/...`、工作区符号链接 | `[实测]` |

### 16.2 收敛原则

1. **只读系统集用白名单**，不用 `--ro-bind / /`。
   未列出路径在沙箱内不存在。
2. **符号链接根必须保留**：`/lib`、`/lib32`、`/lib64`、`/libx32`、`/bin`、`/sbin`，
   否则动态加载器失败（见教训 #16.1）。
3. `/proc`、`/sys`、设备按用途最小开放；`/proc/sys` 只读；
   `/proc/cmdline`、`/proc/version` 用空文件只读覆盖。
4. `/etc/resolv.conf` 生成仅含 `nameserver` 的私有文件（`sanitize`，可切 `hide`/`passthrough`）。
5. `/tmp`、`/var/tmp` 归入 `tmpfs_roots`，**无条件**从可写根剔除，
   改绑每会话私有目录（mode 1777，退出即销毁）。
6. 遮蔽是「硬拒绝 + 软遮蔽」两级，且**硬检查先于软遮蔽**；进程内工具必须规范化解符号链接。
7. `mask_dirs` 可配置、默认开启，命中走审批弹窗（批准仅对该次调用解除对应条目）；
   无审批界面时 fail-closed。
8. **沙箱自身存储在 unmask 下永不被解除**。

### 失败教训

> **#16.1 `/usr` 子树白名单一挂就 `execvp: No such file or directory`**
> 症状：只挂 `/usr/bin`+`/usr/lib` 后任何二进制都启动不了。
> 根因：ELF 解释器路径是 `/lib64/ld-linux-*`，而 `/lib64` 是指向 `usr/lib64` 的**符号链接**；
> 绑 `/usr/lib64` 不会创建 `/lib64`。
> 修复：保留 `/lib /lib32 /lib64 /libx32 /bin /sbin` 这些符号链接根。
> 教训：**最小化不能把加载器链剪断。**

> **#16.2 `/proc/cmdline` 的隐藏方式**
> 症状：`--bind /dev/null /proc/cmdline` 挂载成功，但读取返回 `Permission denied`，不是干净空读。
> 根因：procfs 特性。
> 修复：`--ro-bind <空文件> /proc/cmdline` 得到空内容。
> 教训：**遮蔽要验证读取行为，不是验证挂载成功。**

> **#16.3 `/tmp` 残留的真正根因不是「tmpfs 不新」，而是 overlay 覆盖了它**
> 症状：可见上一会话/宿主 `/tmp` 残留。
> 根因：`build_overlay_specs` 只在 cwd 位于 `/tmp` 下时才跳过该根；
> cwd 在别处时 `/tmp` 仍被 overlay，lower 就是宿主 `/tmp`。
> 修复：`tmpfs_roots` **无条件**从可写根剔除。
> 教训：**别被表象（tmpfs）骗了，要找到真正覆盖它的那一层。**

> **#16.4 空表语义冲突**
> 症状：`tmpfs_roots={}` 无法表示「关掉」，被当成「用默认」。
> 根因：`_readonly_list` 把空表当默认值。
> 修复：新增 `_config_list` 区分「显式空表」与「未配置」。
> 教训：**配置语义要区分「未设置」与「显式置空」。**

> **#16.5 白名单漏了 `/usr/local/go`**
> 症状：封了 `/usr/local/go_workspace`（GOPATH）顺带把 `go` 弄坏。
> 根因：`go` 在 `/usr/local/go/bin`（工具链），与 GOPATH 是两回事。
> 修复：把 `/usr/local/go` 加入白名单，仍排除 `go_workspace`。
> 教训：**封禁目标要精确到目录语义，别误伤工具链。**

> **#16.6 进程内遮蔽被符号链接绕过**
> 症状：`read_file /proc/self/root/etc/shadow`、`/proc/1/root/root/.ssh/id_rsa`、
> 工作区符号链接均可读到宿主凭据。`[实测]`
> 根因：`fnamemodify(path,":p")` 只规整 `.`/`..`，**不解析符号链接**。
> 修复：新增 `_canonical()`（`vim.fn.resolve`，支持 `/proc/<pid>/root|cwd|fd` 与悬空链接），
> 规范化后再比对；`vim.fn.resolve` 可能返回 `//etc/shadow`，需 `gsub("^/+","/")` 归一；
> `_canonical` 只用 `fnamemodify(:p)`，不用 `vim.fn.expand`（会误展开 `$VAR`）。
> 教训：**遮蔽前先规范化，符号链接是绕过入口。**

> **#16.7 硬/软遮蔽顺序错误**
> 症状：非 `read`/`fs_write` 工具（如 `read_image`）在无审批界面时把硬命中吞掉放行。
> 根因：`mask_entry`（软命中）先于 `is_masked_path`（硬拒绝）。
> 修复：executor 中先硬后软；并补全漏声明的本地路径参数（如 `read_image.file_path`）。
> 教训：**硬边界先于可协商项。**

> **#16.8 遮蔽目录与工作区豁免打架**
> 症状：遮蔽兄弟条目时把工作目录也遮蔽，或审批解除时顺带暴露沙箱存储。
> 根因：作用域与豁免规则不精确。
> 修复：cwd 在某遮蔽目录下时只把「含 cwd 的用户 home」只读暴露，
> 沿 cwd 祖先链遮蔽兄弟条目（含隐藏文件），cwd 子树豁免；
> 沙箱自身存储强制遮蔽，unmask 不得解除。
> 教训：**豁免要限定作用域，且不能豁免自己。**

> **#16.9 非命名空间全局 sysctl 可写**
> 症状：`kernel/randomize_va_space`、`net/ipv4/ip_forward`（共享 netns → 直接改宿主网络）、
> `vm/swappiness` 等可写。`[实测]`
> 根因：见教训 #8.4。
> 修复：`--ro-bind /proc/sys /proc/sys`，一次性封闭所有全局 sysctl 写面。
> 教训：**封闭一个类，而不是逐个文件名。**

> **#16.10 残余边界必须如实声明**
> 共享 netns 下 `/proc/net/tcp`、`/proc/net/unix`、`ip addr/route` 泄露宿主元信息
> （`/proc/net` 是 `self/net` 符号链接，挂载遮蔽失败；netlink 亦绕过挂载）；
> 裸 TCP 到宿主本机仍可达。
> 教训：**无法消除的残余要写进文档并声明为非硬边界，不能假装没有。**

### 17.2 测试纪律

- 测试环境必须记录实际加载代码路径、版本、配置、cwd、文件系统及后端模式，

- 危险语料全量运行于一次性 VM；宿主只运行经过分类的安全用例。
  可能写入内核状态的探针不得被简单称为「只打开所以无副作用」。
- 异步测试确保成功、失败、异常都能结束；**断言失败不能变成等待超时**。
- 套件必须隔离配置、注册表、cwd、缓存、端口和持久状态，不能依赖前序用例残留。
- 555 或 606 个测试通过只能作为历史记录。
  版本出口必须同时给出：当前构建标识、覆盖场景、后端配置、实际结果以及仍未提供的保证。

### 失败教训

> **#17.1 `assert` 前不取反，误把超时当 bwrap 卡死**
> 症状：测试「等待超时」，排查 bwrap 很久。
> 根因：`t.false_(s:find(...))`，命中不存在时 `string.find` 返回 `nil`，`nil ~= false` 抛异常，
> `done=true` 没执行。
> 修复：断言前先 `not`。
> 教训：**先拿到原始输出，再怀疑产品。**

> **#17.2 套件污染 / 顺序相关**
> 症状：SUM+NG+E2E 才挂，单跑都过。
> 根因：`test_tools` 里 `registry.reset()` 清掉全局注册表；`with_config` 配置/沙箱状态跨用例污染。
> 修复：以 `run_all()` 全量为准，不要在自定义子集顺序下结论；端到端用例前 `sandbox.reset()`/`ng.reset()`。
> 教训：**子集结论不可信，先排除状态。**

> **#17.3 并行跑多个 nvim 套件导致抖动**
> 症状：`run_command` 类测试偶发超时；计数 `605/1` vs `606/0`。
> 根因：端口/资源竞争；runner 自身「异步断言失败」fixture 的时序噪音。
> 修复：串行跑；连跑三次确认稳定；识别预期噪声 fixture。
> 教训：**区分预期噪声与真实失败。**

> **#17.4 测试临时目录在 `/tmp`**
> 症状：反复触发 overlay/tmpfs 特例。
> 根因：`vim.fn.tempname()` 让 cwd 落在 tmpfs。
> 修复：写用例时意识到这点，显式选择可写根。
> 教训：**测试环境本身就是一类边界。**

> **#17.5 仓库带大量未提交改动 / 被外部重置**
> 症状：`git diff` 突然为空，看起来自己的改动「没了」。
> 根因：会话中途工作区被外部提交（`2e91af0`）；或大量前序 WIP 混入 diff。
> 修复：核对改动时区分自己改的与已有的；我的改动仍在 HEAD 之上。
> 教训：**先确认工作树状态，再判断改动。**

> **#17.6 测试断言在 root 权限下失效**
> 症状：依赖 `chmod` 权限的测试在 root 下失败。
> 根因：测试前提与实际运行身份不符。
> 修复：识别为预先存在的环境问题，与本次新增无关。
> 教训：**测试身份也是环境指纹的一部分。**

## 第 18 章 落地顺序

按以下顺序推进，每个已开放的平台与功能都先满足对应硬边界，再进入兼容性优化：

1. **统一工作区与候选一致性**：Workspace Service、逻辑状态、删除标记、路径映射、结构化返回。
   目标：连续修改、目录/文件投影、删除捕获、选择性应用全部一致。
2. **启动边界与能力探测**：受信启动器、继承资源收敛、真实路径能力探测、单一路物化/捕获。
   目标：默认安全启动、探测与执行一致、降级有触发条件。
3. **网络、LSP、秘密映射与宿主操作**：显式网络模式、LSP 分片与幂等卸载、三阶段秘密处理、broker。
4. **选择性组合发布与后台调度**：publication_set、不可拆分审批组、持久化/恢复/清理闭环。

### 失败教训

> **#18.1 顺序错了会反复返工**
> 症状：先做网络/审批 UI，后补工作区投影一致性，导致 UI 反复重写。
> 根因：底层不变量未先稳定。
> 修复：按上述顺序，先一致性后能力再体验。
> 教训：**先立不变量，再搭体验。**

## 附录 B 失败模式分类

历史坑集中在五类。排障时可据此决定先怀疑哪一层：

### B.1 安全机制认知类（最危险）

把「看起来安全」当成「实际安全」。特点：静态分析全绿，红队一测就穿。

- capability 挡不住 DAC（#8.4、#16.9）
- 应用层代理 ≠ 硬边界（#9.1）
- `/proc` 符号链接无法遮蔽（#8.9、#16.10）
- 进程内工具绕过遮蔽（#16.6、#16.7）
- fd 继承使 namespace 形同虚设（#8.1）
- 只读声明被当边界（#1.1）

**对策**：所有安全声明必须有「从沙箱内部发起的真实攻击探针」证据（`scripts/sandbox_audit.lua`），
并声明残余边界。

### B.2 双层视图投影类（出现频率最高）

真实磁盘层与沙箱暂存层必须对 AI 呈现同一个世界，任一处投影不一致就出现幽灵对象。
`[实测]` 一次用户测试同时命中幽灵创建、幽灵删除、`file_exists` 翻转、`list_files` 报目录不存在。

- 存在性判断用错 API（#3.1）
- 目录与文件参数混用（#3.2）
- 路径还原只覆盖成功（#4.1）
- 删除态回退真实磁盘（#3.7）
- 目录枚举不合成父目录（#3.11）

**对策**：把「统一工作区服务」作为唯一权威，所有工具走同一投影（第 3、4 章）。

### B.3 挂载与内核边界类

- userns × overlay EINVAL（#5.2）
- overlay 递归重叠（#5.3）
- tmpfs 作 lower（#5.1）
- 挂载顺序与遮蔽顺序（#6.3、#6.4、#6.6）
- whiteout 语义（#7.1）
- 安装期权限 0000（#13.1）

**对策**：能力探测用真实执行路径；一个 attempt 一条物化路径；删除解码覆盖所有 whiteout 形态。

### B.4 测试伪故障类（最耗时）

三个最贵的伪故障：uv 阻塞、防火墙丢包、Deferred 吞断言。
共同点是把「可观测证据没拿出来」当成「产品坏了」。

- 断言前不取反导致超时（#17.1）
- 异步断言被吞（#9.5）
- 同步 system 阻塞事件循环（#9.3）
- 套件污染 / 顺序相关（#17.2）
- 跑旧副本（#0.1）
- 并行抖动与预期噪声（#17.3）

**对策**：先拿原始输出/异步探测/真实请求，再下结论；以全量回归为准；串行排查。

### B.5 流程与文档漂移类

- 改配置漏同步中英文四份文档（#18 落地顺序的隐含成本）
- 文档描述与实现不符（`--ro-bind / /` 已改但文档未改）`[实测]`
- 前提变化后旧方案未作废（#9.8）
- 仓库 WIP 与本次改动混杂（#17.5）

**对策**：配置改动必须同步文档与事件常量；副作用可卸载；每个已开放功能先满足硬边界。

## 附录 D 术语与证据分层

| 术语 | 定义 |
|---|---|
| 逻辑工作区 | 由基线快照 + 暂存 + 删除标记构成的、对工具呈现的世界 |
| 基线 | 未修改的固定快照 |
| 暂存 / staged | 逻辑上的修改，尚未提交到真实磁盘 |
| attempt | 一次隔离执行，使用独立私有可写层 |
| 候选 / candidate | 提交前、不可变、可审查的工作区产物 |
| whiteout | OverlayFS 删除标记（字符设备 0:0 或带扩展属性的普通文件） |
| opaque directory | 目录级不透明标记，隐藏 lower 中的同名目录内容 |
| publication_set | 一次选择性发布所验证的变更集合 |
| 不可拆分审批组 | 跨文件/注册表/服务/防火墙的组合，必须整体审查（不承诺事务原子性） |
| fail-closed | 能力不足或异常时拒绝执行，而非放行 |
| 表示 vs 权限 | 路径还原/占位符/界面隐藏是表示；隔离边界是权限 |
| 证据等级 | `[实测]` > `[官方]` > `[报告]` ≈ `[推断]`（推断需实测方可升级） |

### D.2 使用建议

1. 任何新实现先过第 17 章硬验收表。
2. 任何安全声明附一条「从沙箱内部发起的真实探针」证据。
3. 任何一致性改动同时验证：目录/文件、成功/失败、会话内/热重载后四个维度。
4. 任何结论标注证据等级；`[推断]` 未升级不得写入版本出口。
